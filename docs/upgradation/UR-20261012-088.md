# UR-20261012-088 — A Persona's Bound Guild Could Not Be Changed

**Freeze status:** Executed — 2026-10-14 (see the `v5.5.93` entry in `upgradation/change-log.md`).

---

## 1. The finding

The operator asked to move a persona from one guild to another. There was no way to do it. The PATCH
accepted name, dmBehaviour, shard allocation, status and the presentation fields — but not
`boundGuildId`, which is the field that *is* the persona's single-server binding.

Registering a second persona for the new guild was the only route, which leaves the first one behind and
burns an application id. For an operator who simply wants her in a different server, that is not an
answer.

## 2. The mechanism — why this is not a PATCH field

`boundGuildId` looks like one more column. Three things follow from it, and each is a separate store:

- **Her bindings belong to the OLD guild.** `guild_persona_bindings` is keyed by `(guildId, moduleSlug)`.
  Rows left behind keep marking modules occupied in a guild she no longer serves, so nobody else can
  install them there — the same trap UR-083 found on revoke.
- **Her commands are registered against the OLD guild.** Discord holds them under her application; a
  move that does not clear them leaves her answering in a server she has left.
- **The target guild must exist.** `persona_identities.boundGuildId` is a foreign key to `guilds`, so a
  guild the framework has never seen is refused by the database.

A PATCH that wrote the column would satisfy the API and leave all three untouched.

## 3. What changed

- **`PersonaCommandBindingService.rebindPersona(id, guildId)`** — releases her bindings, then moves the
  row. Idempotent: moving her to the guild she is already bound to is a no-op, not an error. A
  foreign-key refusal is caught and reported by name, because *"violates foreign key constraint"* is not
  something an operator can act on.
- **`POST /twill/personas/:personaId/rebind`** with `{ guildId }` — the operation, and the order in it is
  the substance:
  1. **stop her against the OLD guild** — this clears the commands registered there and closes her
     client. Stopping *after* the move would clear the new guild's commands, which have not been written
     yet, and leave the old ones live;
  2. **move the row**;
  3. **reload her** — which registers her commands in the new guild.
- **The response names the move** — `rebind: { from, to, changed }` — so an idempotent re-run is
  distinguishable from a real change without reading the logs.

## 4. Acceptance criteria

- **ACC-UR-088-1** — `POST /twill/personas/:id/rebind` moves her to the named guild.
- **ACC-UR-088-2** — her old bindings are released, so the modules are installable there again.
- **ACC-UR-088-3** — moving her to the guild she already has is a no-op, not an error.
- **ACC-UR-088-4** — an unknown persona returns `404`; a missing `guildId` returns `400`.
- **ACC-UR-088-5** — a guild the framework does not know is refused with a readable reason.

## 5. Recorded

**A field that other rows are keyed by is not a field.** `boundGuildId` is one column and three
consequences, and the consequences live in three places the column does not. The general form, which is
now the fourth UR in this area to say it: before treating a value as settable, ask what else is keyed by
it and what else is written from it.

**The order of the operations is the operation.** Stop-before-move is not a stylistic choice; the
reverse clears the wrong guild's commands and leaves the right ones live — a bug that would look like
"the move worked but she still answers in the old server", which is exactly the symptom UR-083 was
reported for.

**Idempotence is reported, not assumed.** A re-run returns `200` with `changed: false`. An operator
re-issuing a command after a timeout should not have to diff two responses to know whether it took.

**The registry check arrives as a database error.** There is no guild-exists dependency to inject, so
the foreign key is the gate — and a raw constraint violation is not a message, it is a stack trace. It
is translated here rather than surfaced.
