# UR-20261012-046 — One Enablement Rule, Not Two

**Freeze status:** Executed — 2026-10-12 (see the `v5.5.52` entry in `upgradation/change-log.md`).

---

## 1. The defect

Reported from production: at 18:14 UTC **`/dashboard` failed with "not available in guild
1062427177326497863"**. `dashboard` is a **CORE** module.

Two code paths answered the same question differently:

- **`page-data.ts`** filters a listing with `if (tier === 'core') return true;` — core is always
  enabled.
- **`isModuleEnabledInGuild`** (the dispatch path, which is the one that DENIES a command) read the
  per-guild `guild_module_states` row alone and returned `row.enabled === true && row.state === 'active'`.
  For a core module with a stale `enabled: false` row, that is **false**.

So the page said enabled, the router said denied, and the router wins.

§13.2 settles the intent: **a core module is never uninstallable**, so it can never be disabled. The
row is an override for a module that _can_ be turned off; for core there is nothing to override. A
stale row — from a build predating the core refusal in `uninstallModule` — is therefore fatal to a
command that must never be unavailable.

## 2. The fix

`resolveModuleEnabled(tier, row)` in `module-system/tier-rules.ts` is now **the one rule**:

- `core` → `true`, without consulting the row at all. Correct rather than a shortcut: it makes a stale
  row **inert** instead of fatal.
- no row → the tier default (`defaultEnabledForTier`), so an unconfigured standard module stays enabled
  and a marketplace module stays absent until installed.
- otherwise → `enabled && state === 'active'`.

The dispatch path returns early for core and otherwise delegates to the shared rule, so the two paths
can no longer drift.

## 3. What was NOT changed, and why

`defaultEnabledForTier` is `tier !== 'marketplace'`, so an **admin**-tier module is enabled by default.
That is not a defect and not a "never enabled" tier — what hides an admin module from a member is the
**listing** (page-data excludes admin from the installed list) and the admin-tier gate, not the
enablement rule. Recorded so the two are not conflated.

## 4. Acceptance criteria

- **ACC-UR-056-1** — a core module is enabled for every row state, including a stale disabled row.
- **ACC-UR-056-2** — a standard module follows its row and defaults to enabled with no row.
- **ACC-UR-056-3** — a marketplace module is off until installed.
- **ACC-UR-056-4** — a row that is enabled but not `active` counts as disabled.
- **ACC-UR-056-5** — an admin module follows the tier default and a row still overrides it.
