# UR-20261012-054 — The Persona Page, Rebuilt

**Freeze status:** Executed — 2026-10-12 (see the `v5.5.60` entry in `upgradation/change-log.md`).

---

## 1. The control vanished on the second render

The operator reported the Info control appearing and then disappearing on any switch or refresh. The
cause was exact and mechanical:

```ts
function asPageInteraction(interaction: ComponentInteraction, commandName: string): CommandInteraction {
  return { commandName, user: {...}, guildId: interaction.guildId, reply, deferReply, editReply, … };
}
```

**Every switch and every refresh re-enters the router through this adapter, and it dropped
`memberPermissions` and `isGuildOwner`.** So the first paint — a real command interaction — had the admin
context and drew the control; every re-render had none, `isGuildAdmin` returned false, and the control
was not drawn.

**Fixed at the source:** the component adapter now captures the same permission context the command
adapter does, and `asPageInteraction` carries it into the re-entry.

## 2. Only CLAIMED modules are listed

Core modules are gone from a profile entirely. A core module is shared without dispute — neither a
persona nor the main bot owns it — so listing it under a profile was noise, and it made every profile
look identical. What remains is what a profile actually **holds**:

| Profile      | What it claims                                                                                                                          |
| ------------ | --------------------------------------------------------------------------------------------------------------------------------------- |
| A persona    | **only its bindings.** A standard module the main bot already has enabled is the main bot's; a persona does not inherit it by existing. |
| The main bot | non-core modules **enabled for the guild** that no persona has bound. The moment a persona binds one, it leaves the main bot's list.    |

## 3. The command inventory is gone

Every module's every command was listed under the profile. It is removed: a profile's commands are the
framework's, not a property of the profile, and the inventory buried the one thing that section is for.
The switcher's descriptions now count **claims**, not commands, and a profile with nothing claimed says
so rather than rendering an empty section.

## 4. The switcher sits below the footer

The renderer gained a **trailing** placement: a block may declare itself `placement: 'trailing'` and is
then rendered after the footer instead of before it. The profile switcher is the first user — a selector
acts on the whole page, and the footer closes the content above it.

## 5. The Info control: personas only, and the card carries one thing

- **Never on the main bot's profile.** The main bot is not a persona: it has no OAuth redirect to
  register and nothing to invite. A setup control there was meaningless.
- **The card carries the OAuth redirect callback guide and nothing else.** The install guide and the
  invite button were rejected, and the reason is sound: **Discord publishes no API for an application's
  redirect list**, so whether the URL the card asks for is actually registered cannot be read. A link
  that works only if the operator already did the thing the card is asking for is worse than no link.

## 6. The status assets are redrawn

`status-online-icon.png`, `status-offline-icon.png`, `info-icon.png`, `identity-icon.png` and
`profile-icon.png` are regenerated as **minimalist, thick, bold, white** icons on transparency —
drawn at 4× and downsampled so the edges are clean at the 256px Discord stores. Online is a solid disc;
offline is the same disc emptied to a thick ring; info is that disc with an "i" knocked out; identity is
a card; profile is head-and-shoulders.

## 7. Acceptance criteria

- **ACC-UR-064-1** — a re-render keeps the permission context, so an admin-gated control persists.
- **ACC-UR-064-2** — core is never listed; the tiers are standard and marketplace only.
- **ACC-UR-064-3** — a persona's list is its bindings; the main bot's is its unbound enabled modules.
- **ACC-UR-064-4** — no command inventory is rendered anywhere on the page.
- **ACC-UR-064-5** — the switcher declares `placement: 'trailing'`.
- **ACC-UR-064-6** — the Info control renders only on a persona profile and only for an admin.
- **ACC-UR-064-7** — the setup card carries no link button and no invite.

## 8. Not in this record

**The persona's command REGISTRATION** — that a persona should register the same global and guild
command set as the main bot, clearing stale registrations, with the guild binding as the only
restriction — is a separate change to the runtime and is not part of this rebuild.
