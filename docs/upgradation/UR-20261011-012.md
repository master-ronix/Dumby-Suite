# UR-20261011-012 — Documentation Corpus Governance Remediation

**Identity:** UR-20261011-012 · **Version:** 1.0 (Template v1.0, filled instance) ·
**Date:** 11/10/2026 · **Requester:** operator directive, formalised by Dumby Core Engineering

**Freeze status:** Executed — 2026-10-11 (see the `v5.5.13` entry in `upgradation/change-log.md`).
This record corrects the drifted registers, pointers and side ledgers; it modifies no frozen record
and supersedes none. It is the responsive work order for the `/docs` corpus audit of 11/10/2026.

**Basis:** the operator-supplied directive to audit `/docs` end-to-end and raise the resulting
remediation as an upgradation request (11/10/2026) — **final authority**. Every requirement below
is traceable to a finding of that audit (F#); anything not traceable is out of scope.

**Scope rule.** The corpus is the object, not the target of the code work order. This record
changes **documentation, ledgers, and two gate scripts only** — no application source under
`apps/main/src/`. Where a finding is a documentation statement that contradicts the tree, the tree
wins and the document is corrected.

---

## 1. Summary

The `/docs` corpus is a large, gate-verified, code-grounded documentation system: **240 files**,
**172 front-mattered artifacts**, **25 self-verifying gates** (all green at audit time), a
**2,246-row** coverage ledger with **0 orphans**, **584** preserved entities, and a
**22/22-match** docs↔code reconciliation ledger. As a *machine-verified corpus* it is in good
health.

The audit found that the corpus's **governance and provenance layer** — the registers, the
authority pointers, and the side documents that sit outside the gate scope — has drifted from the
tree it describes. The gate suite passes because the drifted statements live in files the gates do
not read. This record asks for the drift to be closed and, where the class of drift is mechanical,
for the gate suite to be extended so it cannot recur.

It is a **correction + hardening** request, not a greenfield build.

## 7. Risks & open questions

- **Second-tree disposition (R7) is a judgement call.** Governing `apps/main/docs/` is more work;
  declaring it out-of-corpus is cheaper but must not orphan real content (the `runbooks/`,
  `security/`, `privacy/`, `compliance/` files are load-bearing). The operator decides (a) or (b).
- **Two ADR series.** `adr/ADR-001…015` and `apps/main/docs/adr/001…005` overlap in subject
  (directory layout, scope) with divergent wording. Merging them is content work beyond a pointer
  fix; R7 asks only that one be made normative.
- **Branch divergence (OI-7).** The corpus is anchored to `feature/dev`; `main` is not reconciled.
  R4 re-points to `feature/dev` HEAD only. The `main` decision remains open.
- **Human attestation (OI-1).** Every artifact still reads `review_state: pending-evidence` /
  `last_verified_commit: null`. This record does not close OI-1; it only stops the *machine*
  ledgers from contradicting each other.
- **A new gate is a new failure surface.** R8's side-doc gate must be scoped so it does not fail on
  legitimately frozen `_inbox/**` or `archive/**` prose.
