## 1. Summary

At HEAD (`feature/dev` @ `3ee7fa53`) the `docs/` corpus is **not gate-green**: `check-side-docs`
fails on a stale directory-entry count, yet the side documents and the change-log still claim
**27/27 green**. The same stale figure survives a second time in a file the gate cannot see, the
corpus's provenance is split across **four** commits, and the change-log's own version model does not
reconcile. This request asks for one bounded pass that (a) restores **gate-truth** — the gates and the
side documents agree with the tree, (b) **re-unifies provenance** to one commit and makes prose
anchors gate-visible, (c) **reconciles the version model**, and (d) closes the **guard-class gaps**
(one guard per defect class, not per file) that let AU-2, AU-5 and AU-6 hide. It is a remediation and
re-baseline of the corpus, not a greenfield build.

**Verified state at HEAD (`feature/dev` @ `3ee7fa53`, 2026-10-16).** 320 files under `docs/` (268
`.md`, 29 `.mjs`, 22 `.json`, 1 `.yaml`); 250 front-mattered artifacts; 27 documentation gates present,
**26 green / 1 red** (`side-docs`); `status/coverage-ledger.json` 2,246 rows / 0 orphans / 132 targets;
`status/code-reconciliation.json` 22 facts, all `match`, `verified_commit` = `6fd4df9d…`;
`status/capabilities.json` 17 (6 implemented / 1 specified / 10 deferred); 15 normative ADRs; 97 live
`upgradation/UR-*.md` records; tree 1,555 entries / 288 directories / 1,267 files.

## 2. Motivation & the governing conflict (read first)

The corpus's authority rests on three claims — *single-sourced*, *gate-verified*, and
*code-grounded*. The first is genuinely enforced. The second is true only **structurally**, and at
HEAD it is **not even structurally true**: one gate is red while the side documents assert green. The
third is **code-grounded to a commit the corpus no longer ships at** (`6fd4df9d…`, not HEAD
`3ee7fa53…`), and the freshness check that could catch it is **inert without a git work tree** and
merely *warns* in a shallow clone.

The prior full-scope audit (`upgradation/UR-20261015-090.md`) named the risk — "anchor churn" — and
added a gate for the tree-count class (R5) and a freshness failure (R2). One commit later the
tree-count class has recurred and the gate that was meant to catch it **catches only one phrasing**,
so the corpus can be made green while remaining inconsistent. This request **adopts and completes**
the still-open mechanism of `upgradation/UR-20261015-090.md` at the current shipping HEAD and adds
the findings a green gate run cannot see (guard-class gaps, version-model regression, provenance
fragmentation).

Per the project's own governance — *anything that departs from how a thing is already defined goes
through a formal Upgradation Request first* — these are recorded here as one request.

## 4. Requested changes (by workstream)

### A. Gate-truth (do this first)
- **R1 — Restore agreement between the tree and the corpus.** Correct `blueprint/structure.md` **and**
  `spec/architecture/directory-file-structure.md` (both the line-21 and line-227 phrasings) to the
  **generated** entry counts at HEAD (1,555 entries / 288 directories / 1,267 files). Generate the
  numbers; do not type them.
- **R2 — Generalise the tree-count assertion to the defect class.** Extend `scripts/docs/check-side-docs.mjs`
  so it matches **every** phrasing of the form "N entries … N directories … N files" (and the
  "(the live tree, N entries: …)" form), not only `(N entries: N directories, N files)`. Verify
  fail-before / pass-after on each phrasing. Optionally, make the counts a single-sourced token
  (`{{counts.tree_entries}}` &c.) so a transcription cannot drift again.

### B. Provenance
- **R3 — Re-unify provenance to one commit.** Bring every provenance string in the corpus and the side
  documents to a **single** current commit SHA (at HEAD: `feature/dev` @ `3ee7fa53…`): the ledger
  `verified_commit`, its `note`, and every row `resolution`; `GAP_MANIFEST.md` (the "Branch / ref"
  line **and** the point-in-time prose at line 14); `migration/migration-prompt.md` §2;
  `migration-ledger.md` (the R12 line); and `docs/README.md`'s "last independent audit".
- **R4 — Make prose anchors gate-visible.** Extend `scripts/docs/check-side-docs.mjs` (or a new
  `check-provenance.mjs`) to flag **any** 40-hex commit literal in the side documents and the chain
  documents that is not the canonical SHA, so a stale `8355ba4f`/`039da060` cannot sit in prose. Add a
  `verified_at` timestamp so the corpus records the **age** of its last verification.

### C. Records & version model
- **R5 — Reconcile the version model.** Bump the `upgradation/change-log.md` front-matter `version`
  to the highest recorded track (v5.5.97); update the §2 note and the §9 population-status line to the
  same track; resolve the `v5.5.96` / `v5.5.97` disagreement on OI-7 so one status stands.

### D. Guard-class closure
- **R6 — Close the restatement and guard gaps.** Remove the restated UR count from
  `migration/migration-prompt.md` §2 (or add the file to the side-docs guard and widen its regex);
  extend the documentation-gate-count guard to the change-log; and state the 121-vs-97 distinction in
  one line in `upgradation/README.md` next to the `counts.ur_requests` note.

### E. Records hygiene & audit age
- **R7 — Populate or explicitly mark.** Fill the change-log §3 early-version bodies (v1.0.0–v4.6.1)
  **or** mark the section's `status` so an empty body is not read as a completed record; and resolve
  the `migration/migration-prompt.md` residual template tokens (line 151, line 439) — fill them from
  the live ledger or mark them explicitly non-normative.
- **R8 — Record the audit's basis and age.** Add a dated "last independent audit" line that names the
  commit **and** a machine-readable audit-age ledger in `status/`, so audit staleness is visible the
  same way provenance staleness becomes visible under R4.

## 8. Risks, assumptions & open questions

- **Anchor churn.** Re-anchoring to a moving HEAD invalidates itself as soon as the branch moves;
  R4's prose-anchor guard and the `verified_at` age are what keep it honest. Without R4, R3 regresses
  on the next push — as it already has once.
- **Symptom vs class.** R1 alone would make the corpus green while leaving the second stale copy
  hidden; R2 is the load-bearing change.
- **Self-verification.** The corpus is authored and verified by the same program; the change-log's own
  self-verification caveat applies. This request prefers recorded, reproducible evidence over
  self-declared status.
- **Open question — canonical shipping branch.** Whether the corpus's canonical shipping branch for
  provenance is `main` or `feature/dev` (the operator recorded a dual-branch model; the provenance
  strings still name `feature/dev`). This request authorises no branch merge; it records the decision
  only.
