## 1. Summary

At HEAD (`feature/dev` @ `416864b`, 2026-10-17) the `docs/` corpus is **gate-green — 27/27** — and
internally consistent on every axis the gates assert. This audit does **not** re-open that verdict:
the corpus is genuinely the strongest artefact of its kind reviewed here. But a green gate run is a
*structural* proof, not a *truth* proof. Four surfaces on which the corpus's own claims rest are
**not asserted by any gate**, and on each of them the corpus has drifted from what it states:

1. a **generated** artefact (`_generated/tree.md`) is materially stale — it lists 182 files against a
   323-file tree — and nothing regenerates or checks it;
2. the **code-grounded** claim is anchored at `3ee7fa53`, **8 commits behind** the live tip, while a
   landed code behaviour (the persona-side BCCM push) has **no spec section and no reconciliation
   row**;
3. the **audit-age** ledger names a reader that does not exist, so audit staleness is invisible; and
4. the **provenance** branch label (`feature/dev @ 3ee7fa53`) no longer resolves — the named commit
   is now `main`'s tip, not `feature/dev`'s.

This request asks for one bounded pass that (a) puts the generated index/tree under a gate and
regenerates it, (b) re-grounds the reconciliation ledger at HEAD and reconciles the undocumented
behaviour, (c) makes the audit-age ledger real by wiring it to a gate, (d) re-unifies the
provenance branch/SHA pairing, and (e) closes the remaining ungated-ledger and record-hygiene gaps.
It is a remediation and re-baseline of the corpus, not a greenfield build.

**Verified state at HEAD (`feature/dev` @ `416864b`, 2026-10-18).** 323 files under `docs/` (270
`.md`, 29 `.mjs`, 23 `.json`, 1 `.yaml`); 27 documentation gates present, **27 green / 0 red**; tree
1,559 entries / 288 directories / 1,271 files; `status/coverage-ledger.json` 2,246 rows / 0 orphans /
132 targets; `status/code-reconciliation.json` 22 facts, all `match`, `verified_commit` = `3ee7fa53…`;
`status/capabilities.json` 17 (6 implemented / 1 specified / 10 deferred); 16 normative ADRs; **98**
live `upgradation/UR-*.md` records; 23 JSON files and 1 YAML contract parse clean; no secret literal in
the corpus.

## 2. Motivation & the governing conflict (read first)

The corpus's authority rests on three claims — *single-sourced*, *gate-verified*, and
*code-grounded*. This audit finds the first genuinely enforced, the second true but **narrower than it
reads**, and the third **stale at HEAD**.

- **Gate-verified is structural, not exhaustive.** The suite proves the corpus is internally
  consistent; it does not prove the corpus is *true*, and it does not run the application toolchain.
  The 27 gates collectively assert nothing about the four surfaces in §1. A green run is therefore
  fully compatible with a stale generated index, a stale code ledger, a dead audit-age mechanism and a
  mislabelled provenance branch.
- **Code-grounded has a freshness gap the gate cannot see here.** The reconciliation ledger is
  anchored at `3ee7fa53`; `feature/dev` is 8 commits ahead at `416864b`. `check-code-reconciliation`
  is designed to fail on code drift, but it is **inert without a git work tree** — a tarball, an
  archive, or a docs-only checkout sees no drift. This audit detected the drift only through the
  repository API.
- **A generated artefact is trusted but unguarded.** `_generated/tree.md` and `_generated/index.md`
  are declared generated in `manifest.json`, but no gate regenerates them or fails on staleness, so
  they rot silently — and they have.

Per the project's own governance — *anything that departs from how a thing is already defined goes
through a formal Upgradation Request first* — these are recorded here as one request.

## 4. Requested changes (by workstream)

### A. Generated artefacts (do this first)
- **R1 — Regenerate the generated artefacts and make them single-sourced.** Regenerate
  `_generated/tree.md` (and `_generated/index.md`) from the live tree so the listing equals the tree
  (323 files at HEAD), or reduce `tree.md` to a generated view whose scope is stated. Do **not**
  hand-edit: generate the file, as `status/compliance.json` is generated.
- **R2 — Put the generated artefacts under a gate, and single-source the tree counts.** Extend the
  suite (a new `check-generated.mjs`, or an assertion inside `scripts/docs/check-side-docs.mjs`) so
  that a generated artefact that no longer matches the tree **fails the gate** — fail-before /
  pass-after on a perturbed entry. Scope the assertion to the file set the artefact claims to cover,
  and state that scope in the artefact's head. **Also** replace the hand-transcribed entry counts in
  `blueprint/structure.md` and `spec/architecture/directory-file-structure.md` with a generated token
  (as `status/compliance.json` is generated), so that adding a record no longer requires editing count
  literals — closing the DR-11 contradiction and making the README's "single-file operation" true.

### B. Code-grounding
- **R3 — Re-ground the reconciliation ledger at HEAD.** Re-verify `status/code-reconciliation.json`
  against `feature/dev` @ `416864b`; update `verified_commit`, `verified_branch` and `verified_at`;
  and **add rows for the code that landed since `3ee7fa53`** — at minimum the persona-side BCCM push
  (`apps/main/src/bootstrap/bootstrap.ts` `runBccmPush`, `apps/main/src/personas/persona-runtime.ts`,
  migration `20260101000053`) and the profile-context awareness change set (PR #40) — each with its
  doc claim, code truth, `code_ref`, verdict and `resolution`.
- **R4 — Reconcile the undocumented behaviour, or record it as a gap.** Add the missing
  `spec/**` coverage for the persona-side BCCM push (its own application scope, its own token, its
  own `/queue` rename path — see `spec/operations/multi-identity-operation-twill-personas.md`), **or**
  record the divergence explicitly in `status/code-reconciliation.json` as `doc-incomplete`/`code-gap`
  rather than leaving the ledger at an all-`match` verdict. Strengthen `check-code-reconciliation` so
  its freshness assertion **fails closed** (a missing work tree is a skip-with-notice, not a pass) and
  so it flags any commit since `verified_commit` that touched `apps/main` / `packages`.

### C. Audit age
- **R5 — Make the audit-age ledger real.** Either wire `status/audit-age.json` into
  `scripts/docs/check-side-docs.mjs` (so the note's claim becomes true) or correct the note and add a
  dedicated `check-audit-age.mjs` that fails when the corpus's recorded audit commit is older than a
  stated threshold behind the live reconciliation anchor. The mechanism must be *enforced*, not
  merely *present*.

### D. Provenance truth
- **R6 — Re-unify the provenance branch/SHA pairing and make it gate-visible.** Bring
  `verified_branch` / `verified_commit` (and the `audit-age.json` pair, and the "Branch / ref" line in
  `GAP_MANIFEST.md`) to one **current** pairing — the branch that actually resolves to the SHA — and
  extend the provenance guard so a **branch label that does not resolve to its named SHA fails**.

### E. Records, ledgers & hygiene
- **R7 — Close the ungated-ledger and record-consistency gaps.** Reconcile the M74/M82 statements in
  `migration-ledger.md` to one status; add `spec/orientation/definitions.md` to
  `status/section-order.json`; and put a gate over the previously-ungated ledgers (`audit-age.json`,
  `classification.json`, `section-order.json`) so each is either asserted or explicitly marked
  non-asserted.
- **R8 — Record hygiene.** Add the reciprocal `supersedes` field to `adr/ADR-012` / `adr/ADR-013`
  (and gate reciprocity), and apply the "shape, not value" label to the residual template tokens in
  `migration/ledger-template.md` and `orchestration/master-prompt.md`.

## 8. Risks, assumptions & open questions

- **Anchor churn.** Re-anchoring to a moving HEAD invalidates itself as soon as the branch moves;
  R4's fail-closed freshness and R6's branch-resolution guard are what keep it honest. Without them,
  R3 regresses on the next push — as it already has once (AU-3, AU-11).
- **Symptom vs class.** Regenerating `tree.md` (R1) alone would make the file correct while leaving
  it unguarded; R2 is the load-bearing change. Likewise R3 without R4 re-anchors once and rots again.
- **Self-verification.** The corpus is authored and verified by the same program; the change-log's own
  self-verification caveat applies. This request prefers recorded, reproducible evidence over
  self-declared status, and every finding above is reproducible from the tree and the repository API.
- **Environment limit.** The application toolchain (`tsc` / `vitest`) was **not** run: the workspace
  requires Node ≥ 22 and the audit environment provides Node 20.20.2 with no installed dependencies.
  DR-2's code drift was therefore detected through the repository API, not by running the code.
- **Open question — canonical shipping branch.** Whether the corpus's canonical shipping branch for
  provenance is `main` or `feature/dev` remains a recorded decision (the operator recorded a
  dual-branch model). This request authorises no branch merge; it records the pairing decision only.
