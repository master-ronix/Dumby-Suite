# UR-20261011-006 — Browse Page: Home in the Install Dropdown

**Identity:** UR-20261011-006 · **Version:** 1.0 · **Date:** 11/10/2026 ·

**Basis:** the operator's directive on the `/browse` page (11/10/2026), **final authority**.

## 1. The directive (verbatim, formalised)

> "Move home as permanent option on dropdown menu as in slot positioned on top of all options.
> This way we found alternative to home button and you can remove it but consider that we have
> fixed cap for dropdown options and per page module listing."

- **C1 — Home as a permanent dropdown option.** The **Home** function moves into the install
  **String Select** as a **permanent option occupying the first slot**, above every module option.
- **C2 — The Home button is removed.** The standalone Home button in the control row is dropped;
  the dropdown is now the Home control's only surface.
- **C3 — The caps are reconciled.** The install dropdown has a **fixed option cap** (Discord's
  String Select limit, 25) and the page has a **fixed per-page module listing cap**. Reserving one
  dropdown slot for the permanent Home option reduces the module listing to **24 per page**, so the
  listing and the dropdown remain in sync within the 25-option ceiling.

## 3. Requested changes

- **R1 (C1).** `browseBlocks` prepends a permanent **Home** option (label `Home`, the framework's
  white home icon, sentinel value `__home__`) as the first entry of the install dropdown's options.
- **R2 (C2).** The control row drops the Home button; **Discover** remains, and the row is retained.
- **R3 (C1).** The `act` handler routes a dropdown selection of the `__home__` sentinel to the
  **/browse main view** (a search reset) — the same behaviour the Home button had — and installs
  nothing.
- **R4 (C3).** The per-page module listing caps at **24** (`MARKETPLACE_MODULE_CAP`); the dropdown
  cap is **25** (`INSTALL_DROPDOWN_CAP`); the two are defined together so the listing and the
  dropdown stay in sync (24 modules + 1 Home = 25 options).
- **R5 (C1/C3).** The install dropdown is **always enabled** — the permanent Home option means the
  control always has at least one selectable entry, so the former empty-state disabled placeholder
  is retired.

## 7. Risks & open questions

- **Single Home surface.** With the button removed, Home is reachable only through the dropdown.
  If the operator later wants Home reachable without opening the dropdown, a compact control can be
  restored — it is a presentation choice, not a platform limit.
- **Cap arithmetic.** Discord rejects a String Select with more than 25 options; the reservation is
  enforced in code, not merely by convention.
