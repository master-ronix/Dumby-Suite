# UR-20261011-015 — Modules Enablement Read & Developer Attribution

**Identity:** UR-20261011-015 · **Version:** 1.0 (Template v1.0, filled instance) ·
**Date:** 11/10/2026 · **Requester:** operator directive, formalised by Dumby Core Engineering

**Freeze status:** Executed — 2026-10-11 (see the `v5.5.15` entry in `upgradation/change-log.md`).
A code correction; it corrects no frozen record.

**Basis:** the operator's live-surface screenshots (11/10/2026), which show the `/modules` disable
and attribution behaviour not matching the specification. The screenshots are the evidence; the two
defects below are the root causes the code examination then found.

---

## 1. Summary

The operator's screenshots show the live bot rendering a **contradiction**: the `/modules` list reads
`Installed Modules · 8` and includes **Hello World**, while that same module's Info card reads
`Status Disabled — re-enable from /browse`; `/browse` shows *"No modules to install"*; and every page
attributes **`Developed by @master_ronix`** instead of *Quixotic Mnemonics*.

Two code defects produce exactly this. Neither is a missing feature — the features of
`UR-20261011-009/010/011` are present — but two functions carry wrong semantics.

---

## 2. Defect A — the developer attribution (the `@master_ronix` on every page)

- `module-system/developer-registry.ts` mapped `dev_first_party → 'master_ronix'` — the **operator
  handle**, not the developer. The loader passes that value as `devUsername`, and
  `rendering/core-renderer.ts` rendered it as `@master_ronix`.
- The Info card, by contrast, resolves through `rendering/developer-identity.ts`
  (`dev_first_party → 'Quixotic Mnemonics'`). So the page band and the card **disagreed**.
- `SPEC-04-REQUEST-LAYER §1.5/§11.6` and `spec/modules/module-anatomy-manifest.md` §11.2 are
  authority: a framework-shipped surface attributes to **Quixotic Mnemonics** — the display name,
  with **no `@` handle** (the spec band is `-# Developed by Quixotic Mnemonics v5.0.0`).

**Fix (R1).** `developer-registry.ts` resolves the first-party ids to `'Quixotic Mnemonics'`;
`core-renderer.ts` renders the registered value verbatim (the `@` prefix is dropped). The band and
the card now agree, and both match the spec band the tests already assert.

---

## 3. Defect B — the enablement read (the "Disabled but still listed" contradiction)

- `bootstrap.ts` defines **two** enablement readers with **different** semantics:
  - `isModuleEnabledInGuild(moduleId, guildId)` — a missing row falls back to the **tier default**
    (used by command dispatch).
  - `isModuleEnabledForGuild(guildId, moduleId)` — a missing row returned **`false`**, with no tier
    fallback (used by the Info card, the dashboard page gating, and the **event gate**).
- A **standard module has no `guild_module_states` row until it is toggled** (§13: it is enabled by
  default; the row is an override). So `isModuleEnabledForGuild` reported an enabled `hello-world`
  as **Disabled** in its card, while `page-data`'s `enabledStates` (tier default) still **listed**
  it, and `/browse` (correctly) offered nothing. The event gate also **silently dropped** that
  module's events.

**Fix (R2).** `isModuleEnabledForGuild` now matches the other two readers exactly: **default by
tier, override by row** — `defaultEnabledForTier(tier)` when the row is absent, and
`enabled === true && state === 'active'` when present. The card, the listing, `/browse`, dispatch
and the event gate now read the same truth.

## 7. Risks & open questions

- **The `@` removal is a deliberate spec alignment.** If the operator prefers third-party handles
  shown as `@handle`, that is a separate presentation decision; the framework surface is specified
  without one.
- **`state === 'active'` is now required.** A row with `enabled:true` but a non-`active` state
  (e.g. `degraded`) reads as not-enabled — matching `enabledStates` and `isModuleEnabledInGuild`.
- **Live verification.** The unit suite runs in CI; the interaction paths (the card, `/browse`) need
  a live run to confirm end-to-end.
- **`test:unit` could not run in the examination environment** (WebAssembly unavailable there).
