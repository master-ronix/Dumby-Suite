## 1. The corrections (verbatim, formalised)

- **C1 — No introduced dividers.** The operator did not ask for dividers on this page; the ones the
  blocks renderer introduced between the control row, the title, the listing and the dropdown are
  removed.
- **C2 — Controls together, beside the title.** The **Home** control stays **beside** the **Discover**
  control (one row), and both sit adjacent to the `Explore new modules to install` title — not
  separated from it by dividers.
- **C3 — Home returns to /browse.** The Home control on the browse page returns to the **/browse
  main view** (the available-modules listing, resetting any search) — **not** the dashboard home.

## 3. Requested changes

- **R1 (C1).** The blocks renderer emits **no** separator between blocks.
- **R2 (C2).** Discover and Home remain one row, placed directly against the title. *(A Discord
  Section renders its accessory on the right, so buttons cannot sit on the same line as text; the row
  is placed adjacent to the title with no divider — the closest expressible layout.)*
- **R3 (C3).** The Home control carries `dumby:act:<invoker>:home:browse`, and the `act` handler routes
  `home` to re-render the **target** page (browse) with no query.

## 7. Risks & open questions

- **C2 platform constraint.** Buttons cannot be placed on the same line as text in Components v2 (a
