# UR-20261012-039 — Residuals Closed

**Identity:** UR-20261012-039 · **Version:** 1.0 · **Date:** 12/10/2026 ·
**Requester:** operator directive, formalised by Dumby Core Engineering

**Freeze status:** Executed — 2026-10-12 (see the `v5.5.46` entry in `upgradation/change-log.md`).

## 1. Summary

Three residuals, one of which turned out to be a live defect rather than a tidiness item.

## 2. The revision

- **Route B could take the whole disable down (a real defect).** Route B removes a module's commands
  with the owning application's bot token. Opening that token **threw** when the envelope could not be
  unwrapped — and the state write, the override attempt and the BCCM enqueue all sat behind it, so an
  unreadable token broke the disable flow outright. `openBotTokenOrEmpty` returns `''` instead, and
  `deleteGuildCommands` already reports an empty token and returns, so the disable completes through
  the queued deregistration.
- **Refresh no longer drops the chosen profile.** The persona switcher lets a member view a persona
  other than the one running the command; Refresh then re-gathered the state and snapped back to the
  running persona. The selected id now rides on the Refresh control's custom id and is dispatched on
  the page-data query channel. A numeric trailing segment is still a page index, so paging surfaces
  are untouched.
- **Presence fetches an uncached guild.** A guild the client had not cached read every persona as "not
  in this guild". The lookup now falls back to a fetch, so a cold cache is not mistaken for absence.

## 3. Acceptance criteria

- **ACC-UR-049-1** — an unreadable persona token degrades to an empty token, never throws.
- **ACC-UR-049-2** — Refresh keeps the selected profile; paging still pages.
- **ACC-UR-049-3** — an uncached guild is fetched; a cached one is used without a fetch; a failed
  fetch reads absent.
- **ACC-UR-049-4** — `typecheck`, `lint`, `format` green; the corpus gates unchanged.

## 4. Risks & open questions

- **Route B still changes a command's id** when the command is genuinely removed. That is inherent to
  deleting, not a defect: the override path re-reads the guild's commands each time, so it always
  targets current ids, and the BCCM re-creates on enable. Any permission a member set by hand in
  Server Settings → Integrations does not survive that, which is worth stating plainly.
- **The presence fetch costs one request** per persona per render on a cold cache; a cached guild
  costs none.
