# UR-20261026-096 — Corpus Residual Closure

**Identity:** UR-20261026-096 · **Version:** 1.0 · **Date:** 26/10/2026 · **Requester:** operator-directed

**Basis.** An independent full-scope audit of the documentation corpus at `feature/dev` @
`de3bde53910990e93c0956e2758126b3087c59b4`. The audit ran the corpus's own 30 gates and they are
**30/30 green** on a complete checkout — so nothing here is a gate failure. The five findings below

**Numbering note.** This record continues the corpus's **global** counter. The counter reset per day

`UR-20261021-095`). The next value is **096**. The gap at 096–100 is a consequence of DOC-015 and is
addressed there, not silently skipped.

## 1. Objective and rationale

Bring the corpus back to a single, self-consistent state of record after the 2026-10-24/25 code and
re-anchor track. The corpus's value rests on two promises: every claim names the commit it was
verified against, and every chain step is recorded in the change-log. Both promises are currently
broken in ways no gate checks, so the corpus overstates its own currency exactly where a reader is
most likely to rely on it.

The work is documentation-only. No application code, configuration, workflow or protected branch is
touched.

## 5. Dependencies and risks

- **Depends on** nothing outside the documentation corpus. No code track, no workflow, no deployment
  change is required.
- **Risk — the counter's meaning.** Recording 101–104 in the register without stating *why* they sit
  above `095` would leave the next reader believing the counter is broken. The register note must
  state the ordering fact, not just list the ids.
- **Risk — gate regressions from added prose.** `check-normative-markers`, `check-terminology`,
  `check-no-restatement` and `check-section-order` constrain what a corpus file may say. Every edit is
  followed by a full 30-gate run; a gate that fails is fixed, not waived.
- **Risk — the audit was read-only over git.** The connector's `git`/`gh` egress returns HTTP 403 for
  this repository, so the tree was fetched through the GitHub connector API and commits are replayed
  through the same API. Commit SHAs are therefore the API's, not a local `git push`'s.

## 6. Rollback and mitigation

- Each finding is a separate atomic commit on `feature/dev`; revert any one with `git revert <sha>`.
- No finding's fix deletes information. Every correction either adds a supersession clause or retitles
  a heading, so reverting is never required to recover a lost fact.
- No force-push, no history rewrite, no protected-branch change is involved.

## 7. Out of scope

- **`apps/main/docs/`** — the application-local set is declared non-normative and outside this corpus
  and its gates by `README.md` ("Boundary"). It is excluded from this audit by that declared boundary.
- **`archive/v4.5.1/documentation.md`** and **`_inbox/**`** — quarantined legacy and frozen
  pre-restructure source records. Their marker and heading counts appear in the scanner output and are
  deliberately not findings: frozen records are not edited to satisfy a lint.
- **The `{{counts.*}}` token convention** — `status/counts.json` declares the tokens the design and
  `check-counts` / `check-side-docs` require them. A candidate finding was dropped for this reason.
- **`OI-1` human attestation** — a standing, policy-stated item, never faked.
- **The documentation/index.md link-style inconsistency** — `api/` links to `api/README.md` while
  `features/` and `guides/` link to bare directories that hold no `README.md`. On the hosting surface a
  directory link resolves, so this is recorded as an observation, not a defect, and no action is taken.
