# UR-20261012-026 — /persona Profile-Aware Board

**Identity:** UR-20261012-026 · **Version:** 1.0 · **Date:** 12/10/2026 ·
**Requester:** operator directive, formalised by Dumby Core Engineering

**Freeze status:** Executed — 2026-10-12 (see the `v5.5.30` entry in `upgradation/change-log.md`).

---

## 1. Summary

UR-20261011-025 gave `/persona` a block set, but it was hardcoded to the main bot and its command
inventory read as a run-on list. Four operator corrections follow, all of them about making the page
describe the persona that is actually present rather than a fixed assumption.

## 2. The revision

- **Custom indicators.** Every marker on the board is a custom application emoji rather than a
  general unicode glyph: `dumby_status_online`, `dumby_status_offline`, `dumby_info`,
  `dumby_identity`, `dumby_profile`. The assets ship in `apps/main/assets/` and are uploaded once at
  bootstrap by the existing emoji uploader; each falls back to a unicode glyph until the upload
  lands, so a page never renders without an indicator.
- **No restated guild.** The identity line no longer carries a `Bound Server` entry. The page only
  ever lists personas bound to the guild it was invoked in, so naming the guild was noise.
- **A tidier inventory.** Each tier is one header carrying its module count, then one line per
  module — the module's own logo, its name, and the commands it owns. The former repeated
  `**name**` / `-# /command` pair is gone.
- **Profile-aware.** The page opens on the profile of the persona that is *running the command* —
  the persona bound to this module in this guild, else the resident main bot — and lists every
  persona active in the guild. A **profile switcher** (`dumby:act:<invoker>:profile:persona`) lets a
  member move between them without leaving the page.

## 6. Risks & open questions

- **Ownership is keyed on `manifest.name`.** A binding's `moduleSlug` is matched against the
  registry entry's `manifest.name`; the first-party manifests keep the two identical. A future
  module whose slug and name diverge would need this revisited.
- **The switcher only appears when personas exist.** A guild with no registered personas shows a
  disabled switcher; that is the intended empty state, not a fault.
- **A failed persona read degrades, it does not fail.** The page logs `page-data-persona-unavailable`
  and falls back to the main bot alone.
- **Fixed v1.1.** The v1.0 commit failed CI on a fault in the new TEST, not the code: it called
  `provider('persona', 'guild-1', 'main')`, but the provider's signature is
  `(moduleId, guildId, page, query)` — so `'main'` was consumed as the page index and `query`
  stayed undefined, making the page correctly fall back to the running profile (`p-2`). The router
  passes `options.query` in the fourth position, so the production path was always right; the test
  now passes the selected id as the fourth argument.
