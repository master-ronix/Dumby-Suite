# UR-20261012-059 — The Model, Stated Once

**Freeze status:** PROPOSED — not executed. This record states the model so the code can be written
against it once, instead of being corrected a piece at a time.

---

## 1. The model, in the operator's own words

> _"If hello module is enabled by main bot then its property of main bot only; the persona can't enable
> or use that, and same for main bot if persona have claimed any modules."_

> _"If core tier modules are accepted by persona and main bot without any contradiction and dispute
> unlike standard & marketplace tier modules."_

> _"Even persona will register exact same guild specific commands and global commands as main bot as it
> is, but cause its guild bounded, persona bot in other guild will just reject all commands and actions
> by them."_

Three rules follow, and everything else is downstream of them:

**R1 — Core is shared and undisputed.** Every profile runs core. No profile owns it, and it is never
listed as owned. Core commands are registered **globally** by every profile, so they answer in DMs and
in any guild.

**R2 — Standard and marketplace are OWNED, one profile per guild, first come.** A module belongs to
whichever profile claims it in that guild. The other profile can neither use it nor install it.

**R3 — A profile's pages show what IT owns.** `/dashboard`, `/modules`, `/browse` and `/persona` are
rendered by an acting profile and must be scoped to it.

## 2. What the code does today (the disputes the operator is seeing)

| Surface      | Today                                                     | Should be                                                       |
| ------------ | --------------------------------------------------------- | --------------------------------------------------------------- |
| `/modules`   | enabled **for the guild** — no ownership dimension at all | the **acting profile's** owned modules                          |
| `/browse`    | what the **guild** can install                            | plus an **occupancy indicator** when the other profile holds it |
| `/dashboard` | guild-wide                                                | the acting profile's owned modules                              |
| `/persona`   | already scoped by `claimedModulesFor` (UR-054)            | unchanged                                                       |

**This is the root of "persona & main bot's modules are shared not synced".** The ownership data exists —
`guild_persona_bindings`, and `resolveCommandOwner` — it simply is not consulted by these pages.

## 3. The occupancy rule the operator described

> _"If a module is disabled by main bot but enabled by persona ... they can't install it cause its
> occupied by a persona in that guild (show its indicator under dropdown menu), same for opposite."_

> _"If we installed persona bot first then standard tier modules have occupied the standard modules
> first, so adding main bot later will just show alert message that module is already occupied."_

So: the **first profile to claim a standard/marketplace module in a guild owns it**. The other profile
sees it in `/browse` as **occupied**, with the owner named, and cannot install it. The claim is the
existing binding; what is missing is the _refusal_ and the _indicator_.

## 4. Planned changes (not yet written)

1. A single ownership read — `ownedBy(guildId, moduleSlug) -> 'main' | personaId | undefined` — derived
   from the bindings, consulted by every page.
2. `/modules`, `/dashboard` scoped to the acting profile's owned set.
3. `/browse` marks an occupied module and refuses the install, naming the owner.
4. The install dropdown carries the occupancy indicator.
5. A standard module claimed by one profile is not offered to the other as a default.

## 5. Acceptance criteria

- **ACC-UR-069-1** — a module installed by the main bot does not appear as installed for a persona.
- **ACC-UR-069-2** — the first claim wins; the second profile sees the owner named and cannot install.
- **ACC-UR-069-3** — core remains shared, listed under no profile, registered globally by both.
- **ACC-UR-069-4** — every page names the profile it is reporting for.

## 6. Why this record exists

The last four changes each fixed one surface and contradicted another, because the model lived in the
operator's head and in scattered prompts rather than in one place. This is that one place. **No code for
§4 is written until this model is confirmed.**
