# UR-20261012-060 — Required Arguments, and One Guild

**Freeze status:** Executed — 2026-10-12 (see the `v5.5.65` entry in `upgradation/change-log.md`).

---

## 1. "Only some emoji" — eight call sites still borrowed the main bot's ids

UR-057 keyed the emoji registry by application, but gave the readers a **default** scope. Eight call
sites omitted it and silently fell back to the main bot's ids, so on a persona those rendered as the
literal `:name:`:

| Site                   | Control                                               |
| ---------------------- | ----------------------------------------------------- |
| `command-router.ts` ×3 | the Home / Next / Prev nav and the Discover button    |
| `command-router.ts` ×2 | the module decoration and the Home icon               |
| `bootstrap.ts` ×2      | the module Info card's logo and its uninstall control |
| `persona-blocks.ts` ×1 | the Refresh accessory                                 |

My earlier sweep used a regex for CONSTANT names and missed the string literals — the same miss that had
already hidden `dumby_refresh` in `health-blocks`.

**The fix is structural, not another sweep.** The scope is now a **REQUIRED argument** on
`customEmojiRef`, `customEmojiParts`, `moduleIcon` and `commandDecorationIcon`. TypeScript then
enumerated all eight sites itself, and cannot miss a future one.

**Where the scope comes from:** Discord states the application on every interaction, so
`CommandInteraction.applicationId` is now carried by the adapters and is the authoritative value. Inside
the **router** the per-identity option is equally valid, because the router is built per persona. The
**core-frame handlers are shared** across identities, so they take it from the interaction — which is
why the module Info card reads `interaction.applicationId`.

## 2. A persona must act only in its bound guild

A persona registers core commands **globally** (UR-058), so her commands are visible in servers she does
not serve. Nothing refused them: `assertPersonaOwnsCommand` checked module ownership, never the guild.

`assertBoundGuild` now runs at dispatch, before the scope and permission checks. A new
`PersonaBoundGuildError` maps to a new `OUT_OF_BOUND_GUILD` notice — _"This is not my server"_ — which
states the rule rather than failing silently. The main bot sets no bound guild and is unaffected.

## 3. Acceptance criteria

- **ACC-UR-070-1** — the emoji scope is a required argument; no reader has a default.
- **ACC-UR-070-2** — a persona's Info card, nav, Discover, Refresh and uninstall controls use her ids.
- **ACC-UR-070-3** — a bound identity refuses a command in any other guild, with a clear notice.
- **ACC-UR-070-4** — a bound identity still acts normally in its own guild.
- **ACC-UR-070-5** — 30 router tests pass; typecheck, lint, format clean.

## 4. Recorded

**A default argument is a silent fallback.** The same bug appeared twice — once in `health-blocks`, once
across eight sites — because a defaulted parameter lets a caller be _wrong without being incorrect_.
Making it required converted an invisible runtime fault into eight compile errors, which is the only
reason the sweep was complete this time.
