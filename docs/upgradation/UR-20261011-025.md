# UR-20261011-025 — /persona Interface Revision

**Identity:** UR-20261011-025 · **Version:** 1.0 · **Date:** 12/10/2026 ·
**Requester:** operator directive, formalised by Dumby Core Engineering

**Freeze status:** Executed — 2026-10-12 (see the `v5.5.28` entry in `upgradation/change-log.md`).

---

## 1. Summary

The `/persona` page (the Twill control-plane command) had no block set, so it fell back to plain
sections: a `━━ Main Bot (Primary) ━━` group over `label: value` lines, then a run-on command
inventory (`/a /b   /c /d`) and a note. It was functional but flat, and its inventory was hard to
read. This UR gives it the same treatment `/health` and `/modules` already have.

## 2. The revision

- **Reactiveness / responsiveness.** A **Refresh** control sits in-line as the status headline's
  Section accessory (`dumby:act:<invoker>:refresh:persona`), re-dispatching the page so its live
  state is re-gathered on demand. The page renders correctly at all three densities (D/M/C).
- **Interactiveness.** The control is a real, invoker-bound button (the registry's invoker re-check
  applies), and the page's own density control remains in the footer.
- **Attractiveness.** A status-dot headline (`🟢 Main Bot · Online`) over a one-line summary, the
  identity as a single compact field line, and the command inventory grouped by tier with each
  module's commands as code-formatted subtext.

Ordinary deploy. The page's data shape changed, but the block builder is the only consumer.

## 6. Risks & open questions
