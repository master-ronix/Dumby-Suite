## 1. Requested changes (verbatim clauses, formalised)

- **R1 — Drop the duplicate heading.** Remove the in-content "Marketplace" heading; the frame title
  already names the surface.
- **R2 — Discover control at the top.** The search/discover control moves to the top, in the position
  the removed heading occupied.
- **R3 — Install dropdown.** The install dropdown (String Select) takes the position the search
  control previously held (the bottom of the frame).
- **R4 — A generated Discover icon.** A purpose-made bold white magnifier asset, uploaded as an
  application emoji — not a text glyph.
- **R5 — Available-modules listing.** The main page lists the available, **not-installed** marketplace
  modules (ranking/trending is deferred), each carrying the framework's default module logo emoji
  beside its name.
- **R6 — Search as a text input.** The Discover control opens an interactive **modal** text input; on
  submit, the main page content becomes the search results, and the dropdown lists those results.
- **R7 — Result cap + sync.** Search results are capped at 20–25; the dropdown options are synced to
  the shown results.
- **R8 — Rename.** The control is named **Discover** (was "Search").
- **R9 — Inline Info.** Each module carries an **Info** control **in-line after its name** (a Section
  accessory, not a separate row); it shows the module's descriptive content **privately (ephemeral)**.
- **R10 — Instant install.** Selecting a module in the dropdown installs it for the guild.

## 3. Requested changes (by workstream)

### Content (R1, R5, R6, R7)
- `marketplace(query?)`: no `title`; lists the available marketplace modules with the default icon;
  filters by name/description when a query is present; caps at 25.

### Controls (R2, R3, R4, R8, R9, R10)
- **Discover** (R2/R4/R8): a Section at the top with an inline Discover button (the generated
  magnifier emoji) that opens a modal text input.
- **Install dropdown** (R3/R10): a String Select at the bottom; selecting an option enables the module
  for the guild (`guild_module_states`) and re-renders.
- **Inline Info** (R9): each module is a Section whose accessory is an **Info** button; it returns an
  **ephemeral** payload.

### Mechanism (new capability)
- Components v2 **Section** (type 9) with an accessory button.
- A **modal** text input, plus **ephemeral** replies.
- The interaction registry gains an acknowledge mode per control (`update` | `ephemeral` | `none`).

## 7. Risks & open questions

- **Interaction paths are live-only.** Modal opening, ephemeral replies, and the install dropdown
  cannot be exercised by the corpus gates; they need a live Discord run to confirm. The
  render-fallback keeps the page usable if a payload is rejected.
- **Install semantics.** Install enables the module for the guild via `guild_module_states`; the
  module's *code* still reaches runtime through the separate Swastik delivery path.
- **Ranking deferred.** "Hyped/trending" ordering needs an algorithm; the interim is the available
  set (§R5).
