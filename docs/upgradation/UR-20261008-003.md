## 2. Requested Changes

1. The dashboard lists the **module commands**, not their descriptions.
2. Page navigation must not redirect to a module's own page; it lists their commands on the main page.
3. Core modules carry **no separate page** under the dashboard; their commands are listed on the main page.
4. Commands are written inside **backticks**.
5. Each command shows its **module icon/emoji** beside it, on the main dashboard page only. (Core modules have no assets yet, so default emoji are authored for them.)
6. The **"Developed by <dev name>"** line returns to its original position — immediately after the title line.
7. The title is **bold** — e.g. `**Dumby Suite | Dashboard**`.
8. The product is named **"Dumby Suite"**, not "Dumby", everywhere.
9. The **footer** states the **module build id** and the **module developer username** (username, not name — e.g. `@master_ronix`).
10. The **dropdown is replaced** by three buttons: a **Home** button (a white home icon, no text), a **Next page** button, and a **Previous page** button.

---

## 3. Acceptance Criteria

- The dashboard main page lists the core modules' commands only, each with its module emoji, in backticks, and no descriptions.
- No core module has a separate dashboard page.
- The title is bold and reads `Dumby Suite | <page>`; the "Developed by <dev name>" line sits directly beneath it.
- The footer reads `<build id> · @<dev username>`.
- The page carries a Home (icon-only) button and Next/Previous page buttons instead of a dropdown.
- No regressions to other pages; the documentation gate suite stays green.
