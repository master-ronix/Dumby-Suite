# UR-20261012-033 — Twill Persona Registration API

**Identity:** UR-20261012-033 · **Version:** 1.0 · **Date:** 12/10/2026 ·
**Requester:** operator directive, formalised by Dumby Core Engineering

**Freeze status:** Executed — 2026-10-12 (see the `v5.5.38` entry in `upgradation/change-log.md`).

---

## 1. Summary

Every persona feature built in UR-20261012-029/030/031 is inert without a persona, and no persona can
exist because `/twill/personas/register` answered an honest 501. ADR-011 states that the registration
API IS the only persona-creation surface — so serving it **fulfils** that decision rather than
reversing it, and it is what makes the operator's expected flow reachable.

## 2. The revision

- **The registration surface is real.** `POST /twill/personas/register` parses the body, **seals** the
  bot token and the optional OAuth2 client secret (ADR-003 — both are credentials the process must
  read back), derives the token digest, and hands the input to `PersonaCommandBindingService`. It
  answers 201 with identity only.
- **Nothing sealed is ever echoed.** `publicPersonaView` discloses identity and an `oauthConfigured`
  flag — never a sealed envelope, and never the token digest. A test asserts the response body carries
  neither plaintext nor digest.
- **The rest of the surface is served too**, so the control plane is not half-real: the detail,
  status and charter reads, and the binding pair (bind, unbind). Presence is deliberately NOT reported
  here — it needs a gateway, and the /persona page resolves it itself.
- **The entrypoint is wired, and still guarded.** `entry/twill.ts` builds the pool and the services
  inside the `isMainEntry` guard, so importing the module in a test has no side effect
  (ACC-ARCH-0007-2).
- **Parsing and route shapes are unit-testable** without a process: they live in
  `personas/twill-registration.ts`, and the entrypoint only wires a database and a listener to them.

## 4. Acceptance criteria

- **ACC-UR-043-1** — registration seals both credentials and returns identity only.
- **ACC-UR-043-2** — an incomplete body is rejected with a named reason.
- **ACC-UR-043-3** — a duplicate application is a 409.
- **ACC-UR-043-4** — the detail, status, charter and binding routes resolve, 404 on an unknown persona.
- **ACC-UR-043-5** — `typecheck`, `lint`, `format` green; the corpus gates unchanged.

## 5. Rollout

Ordinary deploy. The Twill process now needs `DATABASE_URL` and `ENCRYPTION_ROOT_KEY`, which it
already reads through the shared env schema; it was previously inert, so nothing regresses.

## 6. Risks & open questions

- **The registration gate reads cost signals as false.** ADR-008's free-charter sunset is measured, not
  assumed; while the fleet runs on the shared deployment neither signal is measurable, so
  registration stays open under the free charter.
- **Presence is not resolvable from Twill.** The status read reports registration status only; the
  page resolves guild presence through the gateway.
- **The API is internal-only**, behind `registerInternalAuth`.

## 7. Out of scope

- A persona runtime (hosting a persona's gateway) — not required by the invite/authorize flow.
- Any `_inbox/**` or `archive/**` change.
