## 1. Summary

The first CI run of UR-020 failed on the coverage gate at **64.87% branches against a 65% threshold** —
0.13% short — with the whole of `http/routes/oauth.routes.ts` at **0% branch coverage** (lines 28–174).
The feature was correct; its routes were simply untested. This UR adds those tests and, while in the
file, accepts the callback path the operator had already registered.

- **Route tests.** `oauth-routes.test.ts` drives the routes through Fastify's `inject`: the dashboard
  across all four statuses, the authorize redirect and its cookies, and the callback's state mismatch,
  missing code, success, not-permitted and exchange-failure paths. `command-permission-tokens.test.ts`
  gains the unreadable-refresh-token path.
- **Callback alias.** The callback handler is registered at both `/auth/callback` and the older
  `/oauth/callback`, so a redirect URI the operator already registered under the latter keeps working
  without a portal change. (`OAUTH_REDIRECT_URI` must still match one registered redirect exactly.)
