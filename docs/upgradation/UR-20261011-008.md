## 3. Requested changes

- **R1 (C1).** The content leads with a **status headline** — an overall state dot and word
  (`🟢 Operational` / `🟡 Degraded` / `🔴 Down`) with a compact `-#` summary (uptime · Node · module
  count · guild count). Each subsystem is then **one compact line**: a status dot, the bold
  subsystem name, and its metrics as `-#` subtext. The shouty all-caps title is dropped (the frame
  title already names the surface); the in-content title becomes `System Health`.
- **R2 (C1).** Each subsystem carries a **status** (`ok` / `warn` / `down`) computed from its
  connection state; the **overall** state is the worst subsystem (a critical subsystem — the Discord
  gateway or the database — down is `down`; a non-critical one — the cache — down is `degraded`;
  otherwise `operational`).
- **R3 (C2).** A **Refresh** control sits **in-line with the status headline** (a Section accessory),
  carrying a generated bold white circular-arrow icon (`dumby_refresh`). Selecting it re-dispatches
  the page, re-running the health handler so the report re-gathers its data.
- **R4 (C3).** Every existing data point is preserved (grouped onto each subsystem's metric line).
