## 2. Requested Change

Every unique identifier is **systematically issued**, not assigned ad hoc. UR-007 introduced the numeric types but assigned them with a `max()+1` in the request handler — a race, and not an issuance system.

- One issuer allocates every identity number from a **persisted, atomic sequence**, so ids are unique across processes, restarts and concurrent requests.
- The **Credentials Service** issues the developer number at registration; Swastik records what it is given and mints nothing.
- **Swastik, the deployment service**, issues the build number when it accepts a version, drawing the **same shared sequence**, so build issuance is coordinated with credential issuance.
- The credential handle and the license handle are issued the same way.

## 3. Acceptance Criteria

- No `max()+1`, no uncoordinated random id, anywhere in the issuance path.
- The developer number comes from the Credentials Service; the build number comes from Swastik.
- The two services share one sequence table, so issuance is coordinated.
- The documentation gate suite stays green.
