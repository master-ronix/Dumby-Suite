# UR-20261012-037 — Registrar Authority Verification

**Identity:** UR-20261012-037 · **Version:** 1.0 · **Date:** 12/10/2026 ·
**Requester:** operator directive, formalised by Dumby Core Engineering

**Freeze status:** Executed — 2026-10-12 (see the `v5.5.44` entry in `upgradation/change-log.md`).

---

## 1. Summary

The registration API required a `registrarAuthority` in the body and never checked it. The operator
review flagged this, and it was worse than unchecked: the value was **discarded** — it is not a field
on the persona identity and nothing read it. Anyone holding the internal API key could register a
persona for any Discord application.

## 2. The revision

- **A registrar registry.** `persona_registrars` records `(authority, discordApplicationId)` grants.
  `discordApplicationId` of `''` means "any application", so the registry is not chicken-and-egg.
- **Enforcement where the rule belongs.** `PersonaCommandBindingService.registerPersona` checks the
  grant *before* anything else — before the duplicate check — and throws
  `RegistrarNotAuthorisedError`. **An absent registry refuses every registration rather than waving
  it through**, so a misconfigured deployment fails closed.
- **Two ways in.** The runtime surface `GET/POST /twill/registrars` and
  `DELETE /twill/registrars/:authority/:applicationId` (behind the internal API key), and the boot
  seed `PERSONA_REGISTRAR_AUTHORITIES` — comma-separated, each entry a bare authority or
  `authority=applicationId` — applied idempotently so a fresh install can register its first persona.
- **The right status.** Authenticated-but-not-authorised is a **403**, not a 400.

## 3. Acceptance criteria

- **ACC-UR-047-1** — a recorded authority registers; an unrecorded one is refused.
- **ACC-UR-047-2** — with no registry wired, every registration is refused (fail closed).
- **ACC-UR-047-3** — authorisation is checked before the duplicate check.
- **ACC-UR-047-4** — the seed parses bare authorities, `authority=applicationId`, blanks, and empty.
- **ACC-UR-047-5** — `typecheck`, `lint`, `format` green; the corpus gates unchanged.

## 4. Risks & open questions

- **The registry is the authorisation, the internal key is the authentication.** Both are needed; the
  key alone is no longer sufficient.
- **The "any application" grant is broad by design** — it exists to bootstrap. A production registry
  should prefer explicit `authority=applicationId` grants.
- **No self-service.** Granting requires the internal key; there is no developer-facing surface, which
  is deliberate.
