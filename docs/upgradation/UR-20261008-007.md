## 2. Requested Change

`devId` and `buildId` are **numeric** identifiers, not strings.

- `devId` is the registered developer **number**, issued at developer registration (§15.6).
- `buildId` is the build **number** Swastik assigns per accepted version (§15.8).

Both were modelled as strings across the manifest schema, the module manifests, the DB tables and the provenance/credential code. They are now numbers end-to-end, so the manifest, the registry and the surfaces agree on one type.

## 3. Acceptance Criteria

- The manifest schema requires `devId`/`buildId` as positive integers.
- Every module manifest carries numeric `devId`/`buildId`.
- The DB tables (`developers`, `builds`, `licenses`, deployment records) carry integer `devId`/`buildId`.
- The render identity, the account registry and the footer carry the numeric `buildId`.
- The documentation gate suite stays green.
