## 1. Summary

Several documentation gates verify their substantive conditions only when an input that lives
**outside `docs/`** is present, and skip **silently** when it is not — while still printing `OK`
and exiting 0. A gate that cannot distinguish "verified" from "not run" is a fail-open: its green
result is not evidence. This request makes the skips explicit and countable, and fails closed when
a *canonical* input is absent in CI.

## 2. Business / engineering justification

The corpus's central claim is that its gates *enforce* its invariants (release gates). That claim
is only as strong as the gates' willingness to fail. Today, run from a `docs/`-only checkout,
`check-counts.mjs` silently skips six verifications (`bootstrap_stages`, `shutdown_steps`,
`middleware_stages`, `code_ts_files`, `code_src_ts_files`, `code_migrations`) and `check-side-docs.mjs`
silently skips its manifest-ref and provenance checks. Anyone running "the gates" outside a full
repo — a partial clone, a docs-only CI job, a local reviewer — sees green with those checks never
executed. The invariant is unenforced exactly where it looks most enforced.

## 3. Scope & impact

- **In scope:** `scripts/docs/check-counts.mjs`, `scripts/docs/check-side-docs.mjs`, and the
  CI invocation in `.github/workflows/docs-gates.yml` (add a presence assertion for canonical inputs).
- **Out of scope:** changing *which* conditions the gates test, or the application toolchain.
- **Systems / audiences affected:** the documentation gate suite and everyone who runs it.

## 4. Current state (evidence)

- `check-counts.mjs:46,57,97,116` — code-count checks are wrapped in `if (existsSync('../apps/main/...'))`.
- `check-side-docs.mjs:33,87` — the build-manifest ref and provenance/audit-age checks iterate
  `['../GAP_MANIFEST.md', '../STATUS.md', …]` with `if (!existsSync(f)) continue;`.
- `check-side-docs.mjs:121` — branch membership runs only `if (existsSync('../.git'))`.
- Observed: the suite printed `OK` for both gates and exited 0 in a checkout where those inputs
  were absent. Finding DA-1.

## 5. Proposed change

1. Introduce a small helper (e.g. `requireInput(path, label)`): when a **canonical** input is
   absent, emit `SKIP: <label> (input absent: <path>)` to stderr **and** set a `skipped` flag; under
   CI (`process.env.CI`) treat a missing canonical input as a **failure**.
2. Replace the bare `existsSync(...)` guards in the two gates with the helper, so every conditional
   check is either run, or explicitly reported as skipped.
3. Print a final line distinguishing counts, e.g. `OK: <n> checks run, <m> skipped (inputs absent)`.
4. In `docs-gates.yml`, assert the canonical inputs (`apps/main/`, `GAP_MANIFEST.md`, `STATUS.md`,
   full git history) are present before running the suite.

## 6. Risks & mitigations

| Risk | Likelihood | Mitigation |
|---|---|---|
| Failing CI on a legitimate docs-only job | Medium | Fail closed only under `CI`; elsewhere emit explicit SKIP and a non-zero "skipped" count in the summary |
| A genuinely optional input is made mandatory | Low | Classify inputs as canonical vs optional; only canonical ones fail |
| Behavioural drift from the prior "warn and skip" stance for `.git` | Low | Keep the shallow-checkout warning, but surface it as a counted skip, not silence |

## 7. Rollback / reversal plan

The change is confined to two gate scripts and one workflow step. Revert the commit; the gates
return to their prior silent-skip behaviour. No data or generated artefact is affected.

## 9. Acceptance criteria

- **ACC-UR-20261019-094-1** — Every conditional check in the two gates either runs or emits an
  explicit `SKIP:` line naming the absent input; no check is silently skipped.
- **ACC-UR-20261019-094-2** — Under `CI`, a missing canonical input fails the gate.
- **ACC-UR-20261019-094-3** — The gate summary reports run/skipped counts.
- **ACC-UR-20261019-094-4** — With a full checkout, the suite remains green; with `apps/main`
  removed, the affected checks are visibly skipped (not silently passed).
