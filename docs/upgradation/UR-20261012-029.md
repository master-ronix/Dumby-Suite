# UR-20261012-029 — Persona Context Awareness and Setup Control

**Identity:** UR-20261012-029 · **Version:** 1.0 · **Date:** 12/10/2026 ·
**Requester:** operator directive, formalised by Dumby Core Engineering

**Freeze status:** Executed — 2026-10-12 (see the `v5.5.34` entry in `upgradation/change-log.md`).

---

## 1. Summary

Three operator corrections on the persona board. A Twill registration is **guild-bound**, so the page
must be context-aware about the guild it was invoked in; a persona's active state is a fact about the
guild, not about its registration row; and an admin needs a way to discover the one configuration
value only they can act on.

## 2. The revision

- **Context-aware.** The page lists a persona when this guild registered it (`persona_identities.boundGuildId`
  equals the invoking guild) OR when a binding points at it — the former being exactly "the personas
  this guild registered". The opening profile is the persona bound to this module, else the guild's
  own registration, else the resident main bot.
- **Presence-based status.** A persona is **Active** only when its bot is actually invited and present
  in its bound guild; otherwise **Inactive**, and a retired registration stays **Retired**. Presence
  is resolved at render time through a new injected predicate (`personas/persona-presence.ts`): a bot
  user's id equals its application id, so the main bot resolves the persona's membership by fetching
  that id. The lookup is total — an uncached guild, an absent member or a failed fetch all mean "not
  present", never an error. An unresolvable presence is reported Inactive rather than assumed present.
- **The admin setup control.** A guild admin (owner, Administrator, or Manage Server) sees an
  info-icon control on the page. It opens a **private** card stating the OAuth callback URL the
  persona's Discord application must register under OAuth2 → Redirects, the short guide around it, and
  a **link button** labelled *Invite link of persona to the guild* that opens the dashboard's invite
  flow. Non-admins never see the control.

## 5. Rollout

Ordinary deploy. Presence adds one member lookup per persona per page render, and is skipped entirely
when the guild is not cached.

## 6. Risks & open questions

- **Twill registration is still an HTTP stub (501).** `PersonaCommandBindingService.registerPersona`
  is real, but `/twill/personas/register` returns Not Implemented by design (ADR-011 / the v5.0
  stub). Until that surface is un-stubbed no persona row can exist, so this page renders the main bot
  alone in production today. The page logic is complete and unit-tested against seeded rows.
- **Presence needs the member cache.** A guild the client has not cached reads every persona Inactive
  until it is cached; the failure is logged (`persona-presence-check-failed`) rather than silent.
- **The card does not name the persona.** It is built without page context; the subject reads
  "this guild's persona". Passing the name through is a small follow-up.
