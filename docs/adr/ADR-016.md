# ADR-016: Renderer Context — Profile-Aware Accent, the Ephemeral Grammar & the Interactive Zones

**Status:** Accepted — 16/10/2026
**Deciders:** Dumby Core Engineering — Quixotic Mnemonics
**Supersedes:** — (extends ADR-012's accent rule; adds the ephemeral grammar and the interactive-zone discipline)
**Governing sections:** the renderer and interface-reference divisions of `spec/request-layer/` · the renderer clause of the orchestration prompt · `contracts/ui-renderer.schema.json`

## Context

The Renderer was **context-blind**: it fell back to a single framework accent (amber `#FFCA6D`, ADR-012) regardless of *which profile* triggered the action, so a persona's own pages carried the framework's colour rather than the persona's. It had **no ephemeral grammar** — the private, user-only message class Discord offers was unmodelled — and it treated every component as if it belonged to the one framed page grammar. Its component grammar also stopped short of the full Components-v2 set: no Section accessory thumbnail, no user/role/mentionable/channel select menus, and no explicit rule about *where* interactive components may sit relative to the footer.

Four requirements force a decision:

1. a render triggered by a **persona** must default to **that persona's** accent;
2. a Twill-registered persona with no configured accent must default to a **neutral gray**;
3. **ephemeral** messages need their own grammar (single container, no enforced accent, no density);
4. interactive components need a **zone discipline** (buttons in one place, the rest in another), and the full select-menu family must be available.

## Decision

**1. Profile-aware accent (extends ADR-012).** The Renderer is given the *acting profile* — `{ kind: 'main' | 'persona', id, accent? }`. The container accent resolves in this precedence:

> explicit page/module accent → the acting profile's declared accent → the framework default amber.

The main bot's profile carries no accent, so it lands on amber. A **persona with no configured accent** falls back to a neutral **gray `#808080`** — distinct from the framework amber, so an unconfigured persona is visibly its own surface. A **Twill-registered persona defaults to gray at registration** when no accent is supplied, so the stored value is defined and the API reports it.

**2. The ephemeral grammar (new).** An ephemeral (private) message has its **own** grammar, distinct from the framed page grammar:

- **exactly ONE** Components-v2 container holds everything — never several top-level containers;
- **no accent / colour is enforced** — the container carries no `accent_color`;
- **no density modes, no banner, no identity band, no footer** — the caller composes freely;
- the caller may place **any** content components (text, sections, media, separators, thumbnails) and **any** interactive components (buttons, every select menu) inside.

The only rules are the single container and the absent accent. The message carries the `EPHEMERAL` flag (`1 << 6`) alongside `IS_COMPONENTS_V2` (`1 << 15`).

**3. Inline sections.** A **Section** (type 9) places one to three Text Displays beside a single accessory, which is a **Button** or a **Thumbnail**. This is the in-line button/thumbnail Discord supports; no other accessory is permitted.

**4. The interactive zones.** A framed page has two interactive regions, split by the footer:

- **the BUTTON ZONE — above the footer:** buttons only (Action Rows of buttons).
- **the INTERACTIVE ZONE — below the footer:** every interactive component, with **no restriction on kind** — buttons (Action Rows), the select menus (string, user, role, mentionable, channel) and any interactive block — and no imposed limit on how many a page places there. The button zone above the footer is the page's own action bar; it does **not** exclude buttons from this zone.

**5. The select family.** The Renderer supports the full select-menu set: **String** (type 3), **User** (5), **Role** (6), **Mentionable** (7) and **Channel** (8), each with a minted customId, and — for channel selects — an optional channel-type restriction. Modals carry **short** (style 1) and **paragraph** (style 2) text inputs.

**6. The emoji lifecycle.** Application emojis are **registered, loaded, deleted and pruned** through the core. A module's **own asset directory** (`<moduleRoot>/assets/`) is the source of its emoji images, each mapped to a stable name `dumby_<slug>_<basename>`. A sync registers every declared emoji and prunes managed emojis (`dumby_*`) that are no longer declared; a hand-uploaded emoji is never touched.

## Consequences

- Every render is **context-aware**: a persona's pages default to her accent (or gray), the main bot's to amber.
- The ephemeral class is modelled, not improvised, and cannot accidentally carry the framed grammar's chrome.
- Interactive components have a **fixed placement discipline**, and the full Components-v2 interactive set is expressible.
- The emoji population is **managed**, not append-only — a removed module asset does not leave a dangling emoji.
- `contracts/ui-renderer.schema.json` records the full component-type set, the ephemeral flag, the zone discipline and the complete reason-code set.
- **Invariants:** one container per message; ephemeral messages carry no accent; a persona with no accent is gray, never amber; buttons sit above the footer, and the interactive zone below it accepts buttons and every other interactive component with no kind-restriction; a module emoji lives in the module's own `assets/`.
