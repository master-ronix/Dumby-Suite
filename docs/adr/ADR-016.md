# ADR-016: devId and buildId Are Numeric Identifiers

**Status:** Accepted — 08/10/2026
**Deciders:** Dumby Core Engineering — Quixotic Mnemonics
**Supersedes:** — (refines ADR-015's identity model by fixing the two identifier types).
**Governing sections:** the manifest identity fields (§11.2) · the secured upload pipeline (§15.8) · the credentials service (§22.8)

## Context

ADR-015 separated the four identities but left `devId` and `buildId` typed as strings throughout — the manifest schema, the manifests, the DB tables and the provenance/credential code. The developer id and the build id are numbers: a developer is issued a numeric `devId` at registration, and Swastik assigns a numeric `buildId` per accepted version. A string type forces conversion at every boundary and lets a non-numeric value through.

## Decision

`devId` and `buildId` are **numbers** end-to-end.

- The manifest schema requires both as positive integers.
- The `developers`, `builds`, `licenses` and deployment-record tables carry integer columns.
- The render identity, the account registry (`developer-registry.ts`, keyed by the numeric `devId`) and the footer carry the numeric `buildId`.
- The credential layer stringifies the number only where a secret must be hashed (Argon2id takes a string).

`devName` and `devUsername` remain strings, as before.
