# ADR-005: Tier Volumes Replace /src/modules

**Status:** Accepted — 18/09/2026
**Deciders:** Dumby Core Engineering — Quixotic Mnemonics
**Supersedes:** Legacy ADR 002 — the flat `/src/modules` layout decision, recorded in blueprint §7.3 prose.
**Governing sections:** blueprint.md 5.0.0 §5.4, §7.3, §15.8, §15.9, §41, §13.3 · directory.md 5.0.0 (tree) · CI/CD runbooks

## Context

Legacy ADR 002 placed module storage in a flat `/src/modules` tree seeded through a
registry with an import allowlist. In practice that layout mixes first-party and
marketplace code in one directory, lets tier be a runtime property instead of a fact about
where code rests, keeps module code inside the source tree the compilation and lint
surfaces treat as first-party, and keeps directory.md describing an aspirational tree
rather than the audited one. The command-tree half of the same legacy decision
(`src/core/commands/` split) is resolved by its own merge into `src/commands/`; this ADR
resolves the storage half.

The competing options were:

1. Keep the flat tree and enforce tier with runtime checks over a manifest field.
2. Reorganize within `src/` into tiered subdirectories.
3. Move module storage out of `src/` entirely into per-tier volumes plus staging.

## Decision

Module storage leaves `src/` entirely. Module code rests in four per-tier volumes —
`modules-admin`, `modules-core`, `modules-standard`, `modules-marketplace` — plus
`swastik-staging` for un-promoted uploads. `/src/modules` is deleted. Tier-at-rest is
enforced by volume placement: a module's tier is where its directory lives, not a field
that can drift. Bootstrap performs blind discovery over the tier volumes — no hardcoded
module lists or registry seeds — and first-party modules reach the core volumes through the
same promotion pipeline as anyone else's, never by hand-copying.

## Consequences

- **Migration is a numbered release gate**, not a best-effort footnote: the runbook walks
  every module from `/src/modules` to its tier volume, the loader is cut over, and the
  release does not proceed with the gate open. This is the mitigation for the highest-rated
  layout risk — breaking documented layouts and author muscle memory mid-stream.
- **directory.md** is rewritten to the tier-volume tree in the same phase, reconciled
  against the audited HEAD, so the tree document and the filesystem never disagree.
- **The loader and readiness probe** change: discovery reads the volumes; the readiness
  probe checks live-volume access, contents, and required modules, and returns 503 rather
  than restarting blind.
- **Module authors** see no import-path change for their own module code (they author
  against the `swastik` package), but anything that referenced `/src/modules` paths —
  scripts, CI, docs — must migrate within the window.
- **Invariant:** no module code inside `src/`; no module on a live volume that did not
  arrive through promotion.
