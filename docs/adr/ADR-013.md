# ADR-013: Renderer Grammar — No Version on Surfaces; Module Footer, Dashboard-Only Page Switch, Per-Page Density

**Status:** Accepted — 08/10/2026
**Deciders:** Dumby Core Engineering — Quixotic Mnemonics
**Supersedes:** ADR-009 — the A4 title and attribution grammar.
**Governing sections:** the renderer grammar and module-page sections of the interface reference · the renderer clause of the master-prompt · `contracts/ui-renderer.schema.json`

## Context

ADR-009 adopted the A4 grammar: module identity in the title, developer attribution in the footer slot. The program now changes the end-user surface grammar on four points. Version strings are removed from every user-facing surface. The module-page footer carries the module name followed by the module id in brackets. The page-switch dropdown becomes a dashboard-only property. Density (D/M/C) is declared per page by the module author rather than offered as a global control. The first is absolute; the others restate where the grammar now lives.

The competing options were:

1. Keep the A4 grammar unchanged.
2. Remove version strings and keep the rest of A4.
3. Remove version strings and re-specify the footer, the dropdown scope, and density authority as the program requires.

## Decision

No user-facing surface displays a version string. The module-page footer carries the module name and the module id in brackets, followed by the developer attribution. The page-switch dropdown exists only on the dashboard; module authors declare their own flow actions and interactions with no imposed grammar. Density is a per-page declaration by the module author: a page fixes the density it renders at, and no global D/M/C control is offered. The A4 title grammar is superseded accordingly.

**Attribution.** The developer attribution is retained in the footer, after the module id. The earlier standalone developer-and-version footer line is removed. This settles the two clarification answers in favour of keeping attribution after the id.

## Consequences

- The renderer emits no version string on any surface; the previous developer-and-version footer line is removed.
- The footer format is the module name, the module id in brackets, then the developer attribution.
- The D/M/C footer control is removed as a global utility; each page declares the density it renders at.
- The dashboard is the only surface carrying the module page-switch dropdown.
- ADR-009 is superseded and retained as the historical record.
- **Invariant:** no version on any surface; the footer grammar is fixed as stated; the dropdown is dashboard-only; density is per page.
