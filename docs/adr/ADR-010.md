# ADR-010: Official Accent Colour — Blurple #5865F2

**Status:** Accepted — 18/09/2026
**Deciders:** Dumby Core Engineering — Quixotic Mnemonics
**Supersedes:** The A1 accent guidance (yellow), superseded by this adoption.
**Governing sections:** blueprint.md 5.0.0 §16.5, §20 · interface.md 5.0.0 (accent usage) · master-prompt.md 5.0.0

## Context

The two source references conflict on the accent colour: the raw requirements (A1)
specify yellow; the interface reference (A4, the 24 July 2026 window) specifies blurple
`#5865F2`. The accent colour is one of the two Phase 0 decisions that block pre-implementation
closure (the other is the title & attribution grammar, recorded at ADR-009): the Renderer's
dynamic accent slot, the interface documentation, and the master-prompt identity tokens
all reference a single value that must exist before any of them can be finalized.

The program's standing constraint resolves the source conflict: renderer and grammar
decisions adopt A4 where A1 and A4 disagree. What remained was to fix the single value and
its configurability — an accent that modules or guilds could override would fragment the
visual surface grammar the Renderer exists to unify.

The competing options were:

1. Yellow, per A1.
2. Blurple `#5865F2`, per A4, as the single non-configurable value.
3. A configurable accent with a blurple default.

## Decision

The official accent colour is **blurple `#5865F2`** — a single, non-configurable value
used by the Renderer everywhere. The dynamic accent slot in the Components v2 grammar
always resolves to this value; modules do not set their own accent, and no theming or
configuration surface exists to change it.

## Consequences

- **The Renderer** renders every accent element — dynamic-slot fills, emphasis, and
  interactive-state colours — from the single value; there is exactly one accent in the
  product.
- **interface.md** documents one official accent value in its accent-usage section; the
  A1 yellow guidance is superseded and does not survive anywhere in the corpus.
- **master-prompt.md** binds the personality's accent token to `#5865F2`; identity
  references use the single value.
- **Module authors** get a simpler contract: no accent parameter exists to pass, and
  renderer-derived presentation carries the accent for them.
- **Invariant:** exactly one accent colour ships; changing it requires a superseding ADR —
  it is not a configuration change.
