# ADR-002: Complete DM Prohibition for the Main Bot

**Status:** Accepted — 18/09/2026
**Deciders:** Dumby Core Engineering — Quixotic Mnemonics
**Supersedes:** The Admin-tier DM exception documented at blueprint §17.10 (as carried in the 4.x line).
**Governing sections:** blueprint.md 5.0.0 §17.10, §13.6, §21.2, §22, §35, §16, §28.6 · directive.md 5.0.0 (ban registry)

## Context

The main bot historically carried an exception to the DM prohibition: Admin-tier users
could reach the bot through direct messages. The exception created an out-of-band
operational surface inconsistent with the one-operational-surface principle and with the
ban regime the program otherwise enforces (prefix commands, standard embeds, precompiled
artifacts). It also blurred the boundary with Twixter instances, which have their own
Discord identity and their own legitimate DM expectations.

Removing the exception carries a real risk: operators have historically used the DM
channel during incidents, and cutting it without a verified alternative path could lock an
operator out of a degraded system (risk register, DM-exception item). The mitigations are
the credentialed operator surfaces — CLAI (the SSH console) and PEP — plus the operator
lockout-avoidance paths already specified at blueprint §28.6.

The competing options were:

1. Retain the Admin-tier exception as a documented operational convenience.
2. Prohibit DMs but leave the lockout-avoidance question implicit.
3. Prohibit DMs completely and re-verify the operator paths explicitly.

## Decision

The DM prohibition for the main bot is complete: no tier — Admin included — may dispatch
to the main bot through direct messages, and DM dispatch fails closed at its designated
enforcement layer. Twixter instances are outside this decision: each instance decides its
own DM behavior, since it runs on the guild administrator's own token and identity. The
operator lockout-avoidance paths at blueprint §28.6 are re-verified against CLAI/PEP as
the operator path, so the prohibition never becomes a lockout.

## Consequences

- **Operators** reach the system exclusively through the credentialed CLAI and PEP
  surfaces; §28.6's lockout-avoidance guidance is re-verified and documented as the
  authoritative incident path.
- **directive.md** adds the complete DM prohibition to the ban registry with its four
  enforcement layers and coverage audit, alongside the prefix-command and embed bans.
- **Adversarial testing** includes DM dispatch failing closed at the designated layer; the
  ban holds only if the test does.
- **Twixter instances** document their own DM behavior separately; nothing in this ADR
  constrains a persona instance's channels.
- **master-prompt.md** no longer implies any DM personality channel for the main bot.
- **Invariant:** the main bot's operational surfaces are exactly the credentialed control
  planes — never a conversational side channel.
