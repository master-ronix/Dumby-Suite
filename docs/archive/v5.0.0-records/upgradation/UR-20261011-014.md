2. **One genuine code defect was found and fixed:** `z.coerce.boolean()` in the env schema. It is
   `Boolean(value)`, so the **string `"false"` coerced to `true`**. `BCCM_BATCH_PUSH_DRY_RUN` is one
   of its five fields, and `.env.example` documents *"Set false to send"* — but `false` read as
   `true`, so the BCCM batch push **never actually ran** and a disabled module's commands were never
   deregistered on Discord. This is the root cause of the UR-20261011-013 S2 symptom ("the command
   stays registered/loaded in the guild").

## 2. The defect and the fix

**Defect.** `apps/main/src/config/env.schema.ts` declared five fields as `z.coerce.boolean()`:
`DATABASE_SSL`, `REDIS_TLS`, `TELEMETRY_ENABLED`, `CORE_ADMIN_EVAL_ENABLED`,
`BCCM_BATCH_PUSH_DRY_RUN`. `z.coerce.boolean()` is `Boolean(input)`, and for an environment string
`Boolean("false") === true`, `Boolean("0") === true`. So:
- `BCCM_BATCH_PUSH_DRY_RUN=false` read as `true` — the dry-run could never be turned off, and the
  module-command deregistration never executed.
- `DATABASE_SSL=false` / `REDIS_TLS=false` would read as `true` — silently forcing TLS on.

**Fix.** A strict `envBool(def)` helper — accepts `true`/`1`/`yes`/`on` (case-insensitive) as `true`,
any other non-empty string as `false`, and falls back to the field default when unset or blank.

- **R1 — the helper.** `envBool` replaces `z.coerce.boolean()` on all five fields.
- **R2 — regression tests.** `tests/unit/env-schema.test.ts` gains three cases: the `"false"`/`"0"`/
  `"no"` → `false` contract, the `BCCM_BATCH_PUSH_DRY_RUN` on/off contract, and the `DATABASE_SSL`/
  `REDIS_TLS` stray-`false` case.

## 7. Risks & open questions

- **The dry-run default stays `true`.** The defect was the *coercion*, not the default; flipping a
  documented safety default is the operator's call. With R1 fixed, `BCCM_BATCH_PUSH_DRY_RUN=false`
  now works, so a deployment that wants live deregistration must set it.
- **Live deregistration is still batched (§17.7).** The deny override is instant; the BCCM
  deregistration follows the batch window. This record fixes why the batch never ran; it does not
  change the batching.
- **`test:unit` was not run here** (WebAssembly unavailable in the interception environment). CI is
  the gate.
