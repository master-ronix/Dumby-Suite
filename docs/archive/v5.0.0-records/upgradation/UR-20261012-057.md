# UR-20261012-057 — An Emoji Belongs to One Application

**Freeze status:** Executed — 2026-10-12 (see the `v5.5.63` entry in `upgradation/change-log.md`).

---

## 1. What the operator saw

A page rendered by a persona showed every icon as literal text — `:dumby_browse:`, `:dumby_dashboard:`
— where the main bot shows the icon. Two things were true at once:

- **The persona never registered the emoji set on its own application.** Only the main bot's client ran
  `ensureDefaultModuleEmoji`.
- **The registry was one process-wide map.** `emojiIds` mapped a name to a single id, so a persona's
  page embedded the **main bot's** id.

## 2. Why that renders as `:name:`

A Discord **application emoji belongs to one application**, and a message may only reference an emoji
its own application owns. Sending another application's id does not fail loudly — Discord renders it as
the literal `:name:`, which is exactly the text the operator saw.

The multi-persona runtime hosts personas in the **same process** as the main bot, which is why one
shared map produced this.

## 3. The fix

- **The registry is keyed by application.** `registerModuleEmoji(name, id, applicationId)`, and every
  reader (`customEmojiRef`, `customEmojiParts`, `moduleIcon`, `commandDecorationIcon`) takes the scope.
  **There is deliberately no fallback from one application to another**: an id from the wrong
  application is worse than no id at all, because the unicode fallback renders and the wrong id does
  not.
- **A persona registers the set on its own application.** `ensureDefaultModuleEmoji` takes an
  `applicationId`, and the persona runtime runs it after login via a new `ensureEmojis` seam.
- **The scope reaches the render.** The router carries `residentApplicationId` (a persona passes
  `persona.discordApplicationId`; the main bot passes nothing and uses the default scope, where its own
  uploads land), and passes it to the page-data provider and to the blocks that build their own emoji
  references (`personaBlocks`, `healthBlocks`).

## 4. Acceptance criteria

- **ACC-UR-067-1** — a persona's page carries the persona's emoji ids, never the main bot's.
- **ACC-UR-067-2** — an application with no emojis falls back to unicode, never to another app's id.
- **ACC-UR-067-3** — the persona runtime registers the set on its own application after login.
- **ACC-UR-067-4** — the main bot's behaviour is unchanged (default scope).
- **ACC-UR-067-5** — 113 files, 1161 tests, 0 failures; `typecheck`, `lint`, `format` clean.

## 5. Recorded

**A process-global registry cannot describe a per-application resource.** The map answered "what is the
id of `dumby_browse`?" — but the real question is "what is _this application's_ id for it?", and the
runtime hosts several applications in one process. The wrong answer was silent: nothing threw, the text
simply rendered as `:name:`.
