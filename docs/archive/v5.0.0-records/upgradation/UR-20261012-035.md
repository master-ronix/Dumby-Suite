# UR-20261012-035 — Signing Key Normalisation

**Identity:** UR-20261012-035 · **Version:** 1.0 · **Date:** 12/10/2026 ·
**Requester:** operator directive, formalised by Dumby Core Engineering

**Freeze status:** Executed — 2026-10-12 (see the `v5.5.41` entry in `upgradation/change-log.md`).

---

## 1. Summary

`build-signing-key-invalid` had been carried for several cycles as **an operator config task**: "set
`BUILD_SIGNING_PRIVATE_KEY` to a valid single-line PEM with escaped newlines." It was not a config
task. It was a code bug, and the operator could not have fixed it.

## 2. The defect

The warning's own text names the required format — *"a single-line PEM with escaped newlines"* — and
`createPublicKey` was handed the configured string **verbatim**, with no un-escaping anywhere. So:

- the documented single-line form (`\n` as two characters) fails with
  `DECODER routines::unsupported`;
- a value with real line breaks succeeds — but a hosting variable is a single-line field.

Both documented paths were dead ends. Measured, not reasoned: the escaped form was fed to
`createPublicKey` before and after the change.

## 3. The revision

`normalizeSigningKey(value)` turns the two-character `\n` back into a real line break, and returns a
value that already carries real newlines untouched — so both forms now work. It lives in
`module-system/build-signing.ts` (tested) and is called at both registration sites, so `bootstrap.ts`
stays branch-free. The warning's wording is now true.

## 4. Acceptance criteria

- **ACC-UR-045-1** — the escaped single-line form is accepted.
- **ACC-UR-045-2** — a value with real newlines is unchanged.
- **ACC-UR-045-3** — the normalised single-line form is one Node's parser accepts.
- **ACC-UR-045-4** — `typecheck`, `lint`, `format` green; the corpus gates unchanged.

## 4a. v1.1 — the CI fix

The v1.0 commit failed `Gates` with `ReferenceError: describe is not defined` in the new
`normalizeSigningKey` block: the file imported `test` and `expect` from vitest but not `describe`.
Fixed by importing it. A local guard (`check-test-imports.mjs`) now checks that every vitest global a
test file *calls* is imported — this was the third CI failure from that same class of mistake.

## 5. Risks & open questions

- **A wrongly-escaped value still fails**, and still says so — but now the message is accurate.
- **The key is a real secret.** It is read from configuration and never persisted (finding #21);
  nothing about that changes here.
