# UR-20261012-079 — The Occupancy Note Inverted

**Freeze status:** Executed — 2026-10-14 (see the `v5.5.84` entry in `upgradation/change-log.md`).

---

## 1. How it was found

UR-20261012-078 changed a read every page consults, so the Railway session asked for a look in
Discord — specifically that a persona's `/browse` should show anything the main bot enabled as
**occupied**. That is a good instinct, and the check could be done in code as well as in Discord: the
occupancy path is a pure function of the ownership read.

Tracing it found a defect, and one of my own making.

## 2. The defect

The occupancy note was built as:

```ts
occupiedBy: holder === undefined ? 'the main bot' : 'a persona',
note: holder === undefined
  ? 'Occupied by the main bot in this server — a persona cannot take it'
  : 'Occupied by a persona in this server — the main bot cannot take it',
```

`holder === undefined` was a **proxy** for "the main bot", because an enabled-but-unbound module used
to answer `undefined`. UR-078 made that read answer `'main'` **explicitly** — so the proxy inverted.

A module the main bot enabled began rendering as:

> Occupied by a persona in this server — **the main bot cannot take it**

which is nonsense: the main bot is being told it cannot take its own module, and the holder is
misdescribed as a persona. The ownership change was correct; a consumer that had encoded the *old*
spelling of "unbound" was not.

## 3. What changed

Both spellings are recognised:

```ts
const heldByMain = holder === undefined || holder === MAIN_PROFILE_ID;
```

and the note is built from that. A regression test pins both directions: seen from a **persona**, a
main-bot module is occupied and says *"Occupied by the main bot"*; seen from the **main bot**, its own
module is not occupied at all.

## 4. Acceptance criteria

- **ACC-UR-079-1** — a module the main bot holds reads as occupied for a persona, labelled "the main
  bot".
- **ACC-UR-079-2** — the note never says "Occupied by a persona" for a main-bot module.
- **ACC-UR-079-3** — the main bot's own module is not occupied for the main bot.
- **ACC-UR-079-4** — a bound persona module still reads as "Occupied by a persona".
- **ACC-UR-079-5** — 121 files, 1238 tests, 0 failures; coverage at or above the branch floor.

## 5. Recorded

**Changing a shared read means auditing its consumers, not just fixing the read.** UR-078's own record
says a shared-read change is "only half done when the read is fixed — the comparisons have to agree".
This is the same lesson one level out: the comparisons agreed, and a *presentation* consumer that keyed
on the old sentinel did not. The audit has to reach the strings, not just the logic.

**A proxy for "absent" breaks the moment absence becomes explicit.** `holder === undefined` meant "the
main bot" only while the main bot was never named. Giving the main bot a name did not change the
meaning of the fact — it changed the meaning of the test for it. Where a sentinel is doing double duty
as a value, naming the value is the fix.

**The suggestion to check was worth more than the check would have been.** A Discord look would have
shown "Occupied by a persona" on the main bot's module and prompted exactly this investigation — but
reading the path found it without waiting for a live run.
