## 2. Purpose

Land the change set that reshapes the end-user surface: branding, versioning, the dashboard's dynamic command registry, per-page density, per-module banner/accent/icon, the footer grammar, the dashboard-only page-switch, and the marketplace and module pages.

---

## 3. Requested Changes

1. **Branding.** Remove blurple everywhere; amber `#FFCA6D` is the sole accent fallback.
2. **Versioning.** No version string on any user-facing surface.
3. **Dashboard.** Register the core command list dynamically; remove the static list.
4. **Density.** D/M/C is backend-driven and per page; no global control.
5. **Per-module banner & accent.** Each module may declare its own; absent a declaration, the default banner and amber apply.
6. **Existing modules.** Use the default banner, except the dashboard.
7. **Footer grammar.** Module pages show the module name and the module id in brackets.
8. **Page-switch dropdown.** Dashboard-only; module authors declare their own interactions freely.
9. **Module logo icon.** Declared by the module; the default white icon applies when absent.
10. **Marketplace core flow.** Only marketplace modules are offered; unloaded standard modules are listed too; installed modules drop out of the install dropdown.
11. **Dropdown cap + search.** The install dropdown is capped at 25 options; a search control filters the module list.
12. **Core modules.** No separate dashboard pages; only standard modules carry a page.
13. **BCCM.** Verify and fix the rename/suggestion mismatch; make the command argument required; add a reset action.
14. **Module-specific pages.** Show only the registered commands.
15. **Marketplace main content.** Search, an install dropdown, a per-module info control, and the module logo.
16. **Queue page.** Rewrite.
17. **Modules page.** Installed modules only, with info and uninstall/disable controls and a page-switch divider.
18. **Hello page.** Clean up.

---

## 4. Acceptance Criteria

- No blurple anywhere; amber `#FFCA6D` is the sole accent fallback.
- No version strings in any user-facing UI.
- Dynamic registration confirmed; static lists removed.
- Every behaviour verified per module, with no regressions to unrelated behaviour.
