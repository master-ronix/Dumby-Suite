# UR-20261012-062 — Register and Look Up Under the Same Key

**Freeze status:** Executed — 2026-10-12 (see the `v5.5.68` entry in `upgradation/change-log.md`).

---

## 1. The regression

The operator's screenshots show the main bot rendering the **same decoration box** on every core command
— the _fallback_ — while a persona renders the correct per-module logos. That is the signature of an
emoji lookup that MISSED.

UR-060 made the render resolve an emoji by the application **Discord states on the interaction**, which
for the main bot is its real application id. The main bot's **upload**, however, still passed no
application id and therefore registered under the **default scope** (the empty string):

```ts
await ensureDefaultModuleEmoji(discordClient, logger); // scope ''
```

A persona passes its own id on **both** sides — `persona.discordApplicationId` to the upload, and the
same id to the render — so it matched and kept its icons. The main bot's two keys disagreed, so it lost
all of them. **I changed one half of a pair and not the other.**

## 2. The fix

```ts
await ensureDefaultModuleEmoji(discordClient, logger, applicationId); // scope = the real app id
```

The `applicationId` was already computed one line above. The next boot re-reads the existing emojis by
name and registers their ids under the real application id, so the main bot heals itself without
re-uploading anything.

## 3. Pinned by a test

`tests/unit/module-emoji-upload.test.ts` asserts that the upload registers under the **given** id, that
that application resolves the emoji, and that **another application does not borrow it**. Registration
and lookup can no longer drift apart without a red test.

## 5. Recorded

**A key is a pair, and I changed one end.** UR-060 was right that the _render_ must use the application
the message belongs to; I applied that to the read and left the write on the old default. The persona
path was correct only because it happened to pass its id in both places already — which is exactly why
the symptom looked like "the persona works and the main bot doesn't" rather than like a broken lookup.
