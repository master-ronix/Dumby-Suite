# UR-20261012-032 — Residuals: Rename Validation and Dead Code

**Identity:** UR-20261012-032 · **Version:** 1.0 · **Date:** 12/10/2026 ·
**Requester:** operator directive, formalised by Dumby Core Engineering

**Freeze status:** Executed — 2026-10-12 (see the `v5.5.37` entry in `upgradation/change-log.md`).

---

## 1. Summary

Two residuals were left open by earlier records: the rename/alias validation gap that UR-20261012-027
§6 recorded as a finding, and the navigation control that UR-20261012-027's predecessor recorded as
dead code. Both are closed here.

## 2. The revision

- **A rename/alias name is validated where it is submitted.** `bccm-effects.ts` rejects an illegal
  name with `InvalidCommandNameError` before the entry is queued, instead of accepting it and letting
  the BCCM drop it silently at push time. The rule is the same one the push path enforces, reused
  rather than restated.
- **A formal notice for it.** `NoticeReasonCode` gains `INVALID_INPUT`, with its own heading and
  explanation, and `noticeReasonFromError` maps the new error to it — so a rejected submission renders
  through the standard notice frame rather than as a module fault.
- **The dead navigation control is removed.** `CommandRouter.navigationControl` was declared and never
  called, and `RenderDescriptor.navigation` was never populated; both, and the now-unused
  `NavigationControl` type, are gone.

## 4. Acceptance criteria

- **ACC-UR-042-1** — an illegal rename/alias name is rejected at submit and nothing is queued.
- **ACC-UR-042-2** — a legal name still queues.
- **ACC-UR-042-3** — `InvalidCommandNameError` maps to `INVALID_INPUT`.
- **ACC-UR-042-4** — no dead navigation control remains.
- **ACC-UR-042-5** — `typecheck`, `lint`, `format` green; the corpus gates unchanged.

## 5. Rollout

Ordinary deploy. Behaviour change: a previously accepted (then silently dropped) rename now surfaces
as a formal notice at submission.

## 6. Risks & open questions

- **A rename already queued with an illegal name is unaffected**; it is still dropped at push, and the
  self-describing `bccm-batch-command-skipped` warning from UR-20261012-027 names it.
- **`INVALID_INPUT` is a new notice code**, so any consumer switching exhaustively over
  `NoticeReasonCode` must handle it; the renderer's two switches do.
