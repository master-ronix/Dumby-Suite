## 1. The five corrections (verbatim, formalised)

- **C1 — The install dropdown was missing.** It is present even when the available set is empty: a
  **disabled** select carrying a single placeholder option, so the control never silently disappears.
- **C2 — Move the Discover control to the left of the title.** It moves from in-line **after** the
  title to the control row **before** it.
- **C3 — Bold title.** The title reads **`Explore new modules to install`**, rendered bold.
- **C4 — Discover label.** The Discover control carries the word **Discover** after its icon.
- **C5 — Home control.** Beside Discover, a **Home** control (the framework's white home emoji)
  returns to the dashboard home page.

## 3. Requested changes

- **R1 (C1).** Always emit the install dropdown; when the available set is empty, a disabled select
  with one placeholder option. `StringSelect` gains a `disabled` field; `RenderBlock` a `row` kind.
- **R2 (C2).** Render a **control row** (`{ kind: 'row' }`) before the title, carrying Discover and
  Home. *(Discord renders a Section's accessory on the right, so a control row before the title is
  the closest achievable to "left of the title"; recorded as a platform constraint.)*
- **R3 (C3).** The title block is bold: `**Explore new modules to install**`.
- **R4 (C4).** The Discover control carries `label: 'Discover'` plus its icon.
- **R5 (C5).** A Home control beside Discover, customId `dumby:nav:<invoker>:home:0` (the existing
  navigation handler routes it to the dashboard home), carrying the white home emoji.

## 7. Risks & open questions

- **C2 platform constraint.** A Discord Section places its accessory on the right, so the controls
  cannot sit *left of* the title on the same line; they are placed as a row **above** it. If a
  same-line-left layout is required, it is not expressible in Components v2.
- **Empty-set dropdown.** With no marketplace-tier modules, the select is a disabled placeholder —
  the honest state, since a select requires at least one option.
