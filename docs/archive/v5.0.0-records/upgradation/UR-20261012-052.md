# UR-20261012-052 — Visible But Dead

**Freeze status:** Executed — 2026-10-12 (see the `v5.5.58` entry in `upgradation/change-log.md`).

---

## 1. The trap

`assertBindingAllowed` checks two things — that the guild matches the persona's bound guild, and that no
other persona already owns the module. **It does not consult the guild's module state, and neither does
the command deploy.** So binding a module the guild has **disabled** succeeds:

- the binding is created,
- the command is registered in the guild,
- and **every invocation is then refused at dispatch**, because the persona's router consults the same
  `isModuleEnabledInGuild` the main bot does.

The result is a command that appears in Discord and does nothing. That reads as _"the persona is
broken"_, not as _"the guild turned this module off"_ — and it is precisely the misleading shape that
UR-20261012-047 spent two attempts untangling.

## 2. The fix

The **bindings surface refuses it, by name**, before anything is created:

```
409 Binding refused
module "hello-world" is not enabled in guild 1062427177326497863 —
enable it first (for a standard module, re-enable it from /browse)
```

One `/browse` step, taken at the moment the operator is already thinking about that module, instead of
an hour of debugging a command that silently declines.

The check is optional on the route (`isModuleEnabledInGuild`), so a surface without guild context skips
it rather than guessing. **Recorded limitation:** the dedicated Twill process (`entry/twill.ts`) has no
module registry, so it does not perform this check; the API mount
(`TWILL_ROUTES_ON_API`, the surface in use here) does.

## 3. Acceptance criteria

- **ACC-UR-062-1** — a binding for a disabled module is refused with `409` and names the module.
- **ACC-UR-062-2** — the service is not called for a refused binding.
- **ACC-UR-062-3** — an enabled module binds exactly as before.
- **ACC-UR-062-4** — the check is skipped when no enablement lookup is supplied.
- **ACC-UR-062-5** — full suite green: 113 files, 1153 tests, 0 failures; `typecheck`, `lint`, `format`,
  corpus gates 27/27.

## 4. Recorded

**Two checks that each look reasonable can compose into a state neither of them intends.** "The bind
does not need the module enabled" and "the dispatch respects guild enablement" are individually
defensible; together they create a command that exists and cannot run. Where two gates touch the same
resource, the earlier one should refuse what the later one will not allow.
