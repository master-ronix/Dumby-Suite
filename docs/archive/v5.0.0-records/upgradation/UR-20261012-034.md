# UR-20261012-034 — Twill Surface: Reachability and the Registrar Attestation

**Identity:** UR-20261012-034 · **Version:** 1.0 · **Date:** 12/10/2026 ·
**Requester:** operator directive, formalised by Dumby Core Engineering

**Freeze status:** Executed — 2026-10-12 (see the `v5.5.40` entry in `upgradation/change-log.md`).

---

## 1. Summary

Two review points on UR-20261012-033. **Reachability:** the Twill process is not a deployed Railway
service, so the registration API had nowhere to run. **Attestation:** the body carries a
`registrarAuthority` field, and the review asked how it is checked.

## 2. The revision

- **The registration surface can run on the deployed API server.** A new `TWILL_ROUTES_ON_API` flag
  (default **false**) mounts the Twill persona routes on the API server as well as the dedicated Twill
  process, so the endpoint is usable without provisioning a new Railway service. It sits behind the
  same internal API key as `/admin/`, `/mdis/` and `/operational/`, and the mount is opt-in because
  the endpoint accepts bot tokens and client secrets — the public surface must not grow by default.
- **The registrar attestation is recorded.** It was required by the parser and then dropped: it is not
  a field on the persona identity, and nothing read it. It is now written into the registration log
  line, so it is auditable.

## 3. Authentication, stated plainly

- The surface is authenticated by the **internal API key** (`x-internal-api-key`), compared in
  constant time, answered with 401 on mismatch — the same gate as the other privileged surfaces.
- **`registrarAuthority` is an attestation, not a credential check.** Nothing verifies it, because
  there is no registrar registry to verify it against: the system has no record of who may register
  which Discord application. It is recorded for audit and future enforcement. Treating it as
  authentication would be false assurance.

## 4. Impact matrix

| Artifact | Change |

## 5. Acceptance criteria

- **ACC-UR-044-1** — the Twill surface mounts on the API server only when opted in.
- **ACC-UR-044-2** — `/twill/*` is behind the internal API key.
- **ACC-UR-044-3** — the registration log records the registrar attestation.
- **ACC-UR-044-4** — `typecheck`, `lint`, `format` green; the corpus gates unchanged.

## 6. Risks & open questions

- **Enabling the flag widens the public surface.** It is a privileged endpoint behind the internal key
  and OFF by default; enabling it is a deliberate operator choice, and the dedicated Twill process
  remains the canonical home.
- **The attestation is unverified** (see §3). Enforcing it needs a registrar registry, which does not
  exist; that is a product decision, not a wiring gap.
