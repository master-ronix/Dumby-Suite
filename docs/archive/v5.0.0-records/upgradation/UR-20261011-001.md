## 1. Summary

An upgrade of the **Dashboard page** — the bot's home surface. It corrects the navigation grammar,
relocates the navigation controls inside the frame, makes every module's command list carry the
module icon, fixes the module-page identity so a standard-tier page shows its **own** banner (not
the dashboard's), and syncs the command names shown to the guild's current BCCM state. It is an
**upgrade + correction**, not a greenfield build.

---

## 2. Requested changes (verbatim clauses, formalised)

- **R1 — Navigation grammar.** Every button label is title-cased: `Next page`, `Previous page`
  (was `next page` / `previous page`), and the same for the `/modules` and `/browse` controls
  (`Info`, `Uninstall/disable`, `Search`, `First page`).
- **R2 — Home icon weight.** The Home control's icon is thicker (a filled house glyph, `🏠`).
- **R3 — Controls inside the frame.** The whole navigation row renders **inside** the container, at
  the bottom, **below the footer's divider** — not beside the container.
- **R4 — Static icon beside every module command list.** The module icon that today sits beside the
  core command list on the main dashboard page also sits beside the command list on every module
  page under the dashboard.
- **R5 — New default module icon.** The framework's default module icon asset is regenerated (a
  fresh mark) and used wherever a module declares no `ui.icon`.
- **R6 — Core commands stay combined; core modules never get their own page.** The main dashboard
  page lists the slash commands of **all core-tier modules combined**; only **standard-tier**
  modules carry their own page under the dashboard. (No change; restated as binding.)
- **R7 — Module pages carry their own identity.** A standard-tier module's page resolves **that
  module's** banner, icon and footer — falling back to the **default banner**, the default icon and
  the default accent when the module declares none. In particular, the `hello-world` page shows the
  **default banner**, not the dashboard banner.
- **R8 — Module pages list only that module's commands, under their current name and status.** A
  module page shows **only** the commands that module registers, rendered under their **current
  (BCCM-effective) name** and their **status** — nothing else.
- **R9 — Banner assets.** The dashboard module banner (amber) and the default banner (grayscale) are
  the framework assets, served as `apps/main/assets/dashboard-banner.png` and
  `apps/main/assets/dumby-banner.png`. (Confirmed present and byte-identical to the supplied
  artifacts.)

## 7. Risks, assumptions & open questions

- **R3 placement.** The prior renderer kept action rows top-level on the stated belief that
  interactive components are invalid inside a Components v2 container. The `Component` union in
  `apps/main/src/shared/utils/components-v2.ts` includes `ActionRowComponent` as a container child,
  so the move is type-valid; it must be confirmed against the live Discord API on the real
  toolchain.
- **R2 glyph.** "Thicker" is realised as the filled house emoji (`🏠`); if a specific asset is
  intended, it supersedes this.
- **R8 status source.** Status is read from `guild_command_overrides` (`enabled`/`disabled`); the
  name from `guild_command_renames`. Both are the BCCM guild-side layer.
- **Verification limit.** The application toolchain was not run in the authoring environment; the
  clauses are tree-verified, not toolchain-verified (see the change-log entry).
