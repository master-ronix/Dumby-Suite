## 2. Requested Changes

1. **Control placement.** The page's action controls (Home / Next page / Previous page) sit **below the footer** (module build id · developer username), separated from it by a **divider**.
2. **Registered developer attribution.** The developer attribution is the developer's **platform-registered username**, resolved from the account registry — never a static name. The registry is owned by the credentials service, coordinated with Swastik and the development portal; a manifest's `devId` must match a live registration.
3. **Module icon mechanism.** A module's icon is a **custom Discord emoji**: the manifest's `ui.icon` names it, and the framework's default white icon is used when a module names none. The default icon is bundled as an asset and uploaded once as an application emoji.
4. **No per-page headings.** A page under the dashboard carries **no heading** in its content — the frame title (`Dumby Suite | <page>`) already names it.
5. **Icons only on the main page.** Only the **main dashboard page** shows each command's module icon; a **module-specific page shows none**.

---

## 3. Acceptance Criteria

- Action controls render below the footer, after a divider.
- The attribution resolves to a registered username, not a literal.
- Every module resolves an icon: its declared custom emoji, else the framework's default white icon; no page renders without one.
- Dashboard pages carry no in-content heading.
- Module-specific pages show no icon beside their commands.
- No regressions; the documentation gate suite stays green.
