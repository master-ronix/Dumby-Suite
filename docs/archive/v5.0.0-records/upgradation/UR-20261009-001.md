# UR-20261009-001 — Corpus Re-Anchoring & Provenance Integrity

**Identity:** UR-20261009-001 · **Version:** 1.0 (Template v1.0, filled instance) ·
**Date:** 09/10/2026 · **Requester:** Dumby Core Engineering — Documentation Audit

**Freeze status:** Raised — open. Not yet executed. This is a new request record, raised under its
own ID; it does not modify any frozen record.

**Basis:** the `docs/` corpus audit dated 09/10/2026 (findings F1–F10), executed against branch
`main` @ `9e29e855`. This request is the formal, traceable remediation vehicle for those findings.

---

## 1. Summary

The `docs/` corpus is structurally sound — all 25 documentation gates pass — but its provenance
and its strongest metadata are not anchored to the branch and commit it ships on, and several
normative sections are deliberately empty. This request asks for a single, bounded remediation
pass that (a) re-anchors every provenance claim to one shipping branch and one current commit,
(b) makes the reconciliation ledger self-consistent and gate-enforced for freshness, (c) resolves
the branch divergence as an explicit decision, (d) populates or downgrades the empty normative
sections, and (e) closes the documentation defects that a green gate run cannot see.

Scope rule: every change below must be traceable to an audit finding (F1–F10). Anything not
traceable is out of scope (§10).

---

## 2. Motivation

The corpus's authority model rests on three claims — *single-sourced*, *gate-verified*, and
*code-grounded*. The first is genuinely enforced. The second is true only structurally. The third
is currently false in a reproducible way: the corpus states it was derived from `feature/dev` and
pins `feature/dev` commits, while it ships on `main`, and its own directory reference describes a
tree that does not exist on that branch. A reader or a build agent who trusts the corpus is
trusting anchors they cannot resolve on the branch in front of them.

This is the class of drift the corpus was explicitly built to prevent — the same class the
`v5.3.0` remediation pass closed for three defects (D1–D3). Those defects were caught by an
independent examination, not by a gate. This request closes the remaining ones and, where feasible,
moves their detection into the gate suite so they cannot recur silently.

## 4. Requested changes

### R1 — Re-anchor provenance strings to the shipping branch and one commit *(F1)*
Update every provenance claim in the normative corpus to name the **canonical shipping branch**
and a **single current commit SHA**, replacing the `feature/dev` / mixed-commit anchors. Files in
scope include `blueprint/structure.md`, `spec/architecture/directory-file-structure.md`, and the
note field of `status/code-reconciliation.json`. The entry count in the directory reference must
be regenerated from the canonical branch (currently stated as 921; the `main` tree is 1,353).

### R2 — Collapse `status/code-reconciliation.json` to one HEAD and make it self-consistent *(F1, F2)*
Set `verified_commit` to the single canonical commit; replace the six row `resolution` strings that
cite a different HEAD with the same canonical commit; reconcile REC-017's anchor. The ledger's
`note` and `verified_commit` must agree.

### R3 — Record an explicit decision on the branch divergence *(F3)*
`main` is 18 commits behind `feature/dev` and lacks ADR-012…014 and the `upgradation/UR-20261008-*`
records. Request: **decide and record** whether those commits are (a) landed onto the shipping
branch, or (b) deliberately absent. This request does **not** authorise a `feature/dev` → `main`
merge; that direction is explicitly out of scope (§10) and requires its own instruction. The
decision is recorded in `upgradation/change-log.md` and, if it changes architecture, an ADR.

### R4 — Populate or downgrade the empty normative sections *(F4)*
Fill `upgradation/change-log.md` §9.1 (Scope & Method), §9.2 (Master Version Table), §9.4
(Cross-Version Defect Lifecycle), and §9.5 (Open Items Carried Forward) — or, if they cannot be
filled now, re-state their `status` so an empty section is not read as a completed normative record.
Populate `STATUS.md` (Current State, Module Delivery Boundary) from the current tree, or reduce it
to a pointer with an explicit "not yet populated" marker.

### R5 — Give `review_state` / `last_verified_commit` a real lifecycle *(F5)*
Either run a human review pass that flips at least the load-bearing normative sections
(`spec/governance/**`, `spec/request-layer/permission-authorization-engine.md`,
`spec/modules/module-anatomy-manifest.md`, `contracts/**`) to `review_state: verified` with a
populated `last_verified_commit`, **or** state as corpus policy (in `README.md` and the
front-matter schema note) that the corpus is machine-verified only and that the two fields are
reserved. A field that is always `null` must not be presented as evidence.

### R6 — Add a provenance/freshness gate *(F2, F9)*
Extend the gate suite (or `scripts/docs/check-code-reconciliation.mjs`) so CI fails when the
reconciliation ledger's `verified_commit` is older than the corpus's declared basis, when a
provenance string names a branch other than the canonical one, or when a `resolution` cites a HEAD
that disagrees with `verified_commit`. This moves F1/F2-class drift from audit-detectable to
gate-detectable.

### R7 — Close the documentation defects in the reader-facing docs *(F1, F6, F7)*
- Correct the gate-run instruction in `README.md` (docs) to state `cwd = docs/`, matching the CI
  `working-directory`.
- Refresh or delete the repository-root `replit.md`; if kept, mark it clearly as historical and
  correct its migration/test/ADR counts (45 migrations · 865 unit tests / 85 files · 11 ADRs) and
  its module-location statement (`packages/modules/<slug>/`, no `src/core/` wrapper).

### R8 — Confirm the frozen-inbox quarantine *(F8)*
No change requested. Confirm in `upgradation/README.md` that the retired `docs/ur/` path persists
only inside the frozen `_inbox/` and must never be quoted forward into the live corpus. This is a
provenance confirmation, not an edit to frozen content.

### R9 — State the version model *(F10)*
Add one statement (in `README.md` (docs) or the manifest) mapping `corpus_version` to its parts,
so `5.0.0` / `5.2.0` / `5.3.0` across the corpus resolve to a defined meaning rather than six
unrelated numbers.

## 6. Acceptance criteria

- **ACC-UR-001-1** — No provenance string in the normative corpus names a branch other than the
  canonical shipping branch; every cited HEAD equals the ledger's `verified_commit`.
- **ACC-UR-001-2** — `status/code-reconciliation.json` contains exactly one distinct commit SHA
  across `verified_commit`, `note`, and all `resolution` fields.
- **ACC-UR-001-3** — The branch-divergence decision (R3) is recorded in `upgradation/change-log.md`.
- **ACC-UR-001-4** — Every section of `upgradation/change-log.md` §9 is either populated or
  explicitly marked non-normative; `STATUS.md` is populated or explicitly a pointer.
- **ACC-UR-001-5** — Every front-mattered file is either `review_state: verified` with a
  non-null `last_verified_commit`, or covered by a stated machine-verified-only policy.
- **ACC-UR-001-6** — A provenance/freshness gate exists and fails on a deliberately injected
  stale anchor (fail-before / pass-after).
- **ACC-UR-001-7** — `cd docs && for g in scripts/docs/check-*.mjs; do node "$g"; done` passes
  100% after the changes, with the new gate included.

## 7. Rollout

1. R6 (gate) first — so subsequent edits are checked as they land.
2. R1 + R2 together — the re-anchoring and the ledger must move as one change.
3. R4 + R5 — populate the normative/evidence surfaces.
4. R3 — the branch decision (may be deferred pending an operator decision; it is a recorded

5. R7 + R8 + R9 — reader-facing docs and version model.
6. Re-run the full gate loop; append the `v5.3.x` entry to `upgradation/change-log.md` per the
   change-log discipline.

---

## 8. Risks

- **Anchor churn.** Re-anchoring to a moving HEAD invalidates itself as soon as the branch moves;
  R6's gate is what keeps it honest. Without R6, R1/R2 regress on the next push.
- **False "verified".** Flipping `review_state` without a real review would manufacture evidence —
  R5 permits a policy statement precisely to avoid that.
- **Scope creep.** The branch divergence (R3) touches decisions, not just docs; it is deliberately
  bounded to *recording a decision*, not executing a merge.
