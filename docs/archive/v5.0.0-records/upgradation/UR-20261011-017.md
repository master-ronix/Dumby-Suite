# UR-20261011-017 — Disable Button Non-Functional

**Identity:** UR-20261011-017 · **Version:** 1.0 (Template v1.0, filled instance) ·
**Date:** 11/10/2026 · **Requester:** operator directive, formalised by Dumby Core Engineering

**Freeze status:** Executed — 2026-10-11 (see the `v5.5.17` entry in `upgradation/change-log.md`).

**Basis:** the operator's report (11/10/2026) that the module **Disable button is not functional at
all**, confirmed on the now-live build. This record gives the root cause and the fix.

---

## 1. Summary

The disable path wrote the guild-module state with a Knex upsert whose `ON CONFLICT` target did not
match the table's unique index, so the write **threw** and the module was never disabled — the button
appeared to do nothing.

`guild_module_states` is guarded by a **partial** unique index (the migration helper
`createPartialUniqueNotDeleted` builds
`... on "guild_module_states" ("guildId", "moduleSlug") where "deletedAt" is null`). Postgres matches
an `ON CONFLICT` target to a partial index **only when the target repeats the predicate**. The three
`guild_module_states` upserts used the bare form `.onConflict(['guildId', 'moduleSlug'])`, which
matches **no** index, so every insert failed with **SQLSTATE 42P10** ("there is no unique or exclusion
constraint matching the ON CONFLICT specification"). `uninstallModule` is not wrapped in a try/catch,
so the failure propagated and the disable was a no-op.

---

## 2. The fix

The three upserts now carry the index predicate — the codebase's own idiom, already used for
`guild_command_renames` (`admin.routes.ts`) and `approvals` (`approval.repository.ts`):

```
.onConflict(db.knex.raw('("guildId", "moduleSlug") where "deletedAt" is null'))
```

- **R1 — disable (`uninstallModule`).** The disable upsert now matches the partial index; the state
  write (`enabled:false, state:'disabled'`) persists, then the `@everyone` deny override and the BCCM
  enqueue run.
- **R2 — enable/install (`installModule`).** The same defect blocked `/browse` installs; fixed the
  same way.
- **R3 — default-row seed (`isModuleEnabledInGuild`).** The seed insert carried the same defect (it
  was swallowed by a try/catch, which is why no per-guild row was ever created for a standard module);
  fixed.

**Proof.** The generated SQL now reads
`on conflict ("guildId", "moduleSlug") where "deletedAt" is null do update set …` (it previously read
`on conflict ("guildId", "moduleSlug") do update set …`). A DB-free regression test
(`tests/unit/module-state-upsert.test.ts`) locks the contract.
