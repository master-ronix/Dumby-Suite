# UR-20261012-064 — One Source for the Scope

**Freeze status:** Executed — 2026-10-12 (see the `v5.5.70` entry in `upgradation/change-log.md`).

---

## 1. The report

The Home control fell back to the unicode glyph on every page, and most icons did so across module
pages.

## 2. The cause

Five router call sites resolved the scope from a **per-router option**:

```ts
this.options.residentApplicationId ?? DEFAULT_EMOJI_SCOPE;
```

That option is **undefined for the main bot**, so the lookup used the empty scope — while the main bot's
upload keys by its real application id (UR-062). Every one of those lookups missed: the Home control in
both navigation rows, the Discover control, the module decoration, and the browse Home option.

I had reverted those five to the option myself, when fixing a type error, on the reasoning that "inside
the router the per-identity option is the authority". That is true for a persona and false for the main
bot — which is exactly the half that broke.

## 3. The fix — one source, compiler-enforced

`residentApplicationId` is **removed from the router options entirely**, and a single accessor replaces
it:

```ts
private emojiScope(interaction: CommandInteraction): string {
  return interaction.applicationId ?? DEFAULT_EMOJI_SCOPE;
}
```

Discord states the application on every interaction, and that is the same value the upload keys by. With
the option gone, TypeScript enumerated every site that had not decided which application it renders for —
including the two helper methods (`pageActions`, `browseBlocks`), which now take the scope as an explicit
argument because they have no interaction of their own.

**There is deliberately no second source.** A default, or a fallback option, is what let the read and the
write disagree twice.

## 4. Acceptance criteria

- **ACC-UR-074-1** — the router has exactly one emoji scope, taken from the interaction.
- **ACC-UR-074-2** — no router option can supply a scope.
- **ACC-UR-074-3** — 115 files, 1169 tests, 0 failures; coverage 68.31% branch, no threshold error.
- **ACC-UR-074-4** — typecheck, lint and format clean.

## 5. Recorded

**The same bug, three times, from the same cause: two sources for one key.** UR-060 made the read
authoritative and left the write on the default; UR-062 brought the write into line; and this record
removes the last alternative source. Each time the fix was to delete a second way of asking the question,
not to make the answers agree by hand.

**Still open (recorded, not fixed):** the framework's icon assets are listed in the **core**
(`module-emoji-upload.ts`), including the first-party module logos. The docs describe modules as
independently developed with their own asset paths, so those belong to the modules. That is a separate
change and is not made here.
