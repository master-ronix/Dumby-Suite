# UR-20261011-002 — Dashboard Page: Iconography & Fallback Corrections

**Identity:** UR-20261011-002 · **Version:** 1.0 · **Date:** 11/10/2026 ·
**Requester:** operator directive, formalised by Dumby Core Engineering

**Freeze status:** Executed — 2026-10-11 (see the dated entry in `upgradation/change-log.md`).
This record corrects `UR-20261011-001`; it modifies no frozen record.

**Basis:** the operator's three corrections to the dashboard page (11/10/2026), **final authority**,
which override the corresponding clauses of `UR-20261011-001` where they conflict.

---

## 1. The three corrections (verbatim, formalised)

- **C1 — Iconography by surface (corrects UR-20261011-001 R4).** On the **dashboard main page**, each
  **core-tier module's** command carries **that module's own logo icon emoji** beside it — not a
  single shared default. On a **module-specific page**, the command carries the framework's **default
  white icon**. (The first pass used one icon for both surfaces; only the module-page half was right.)
- **C2 — A generated Home icon (corrects UR-20261011-001 R2).** The Home control carries a
  purpose-made **bold, thick, white** house icon — a generated asset, not the `🏠` emoji substituted
  in the first pass.
- **C3 — Module-page banner fallback (restates UR-20261011-001 R7).** A module page whose module
  declares **no banner** must render the framework's **default banner** (grayscale) — never the
  dashboard's own banner. A module with no assets (the `hello-world` module: no logo, no icon, no
  banner) is exactly the case the framework's fallbacks exist for.

---

## 3. Requested changes

- **R1 (C1).** Give each first-party core module its own logo icon: a bundled white line-art asset
  per module, uploaded once as an application emoji (`dumby_<slug>`), declared as the module's
  `ui.icon`. The main page then resolves each core command's own icon; a module page keeps the
  default white icon.
- **R2 (C2).** Bundle a generated bold white Home icon asset and use it as the Home control's emoji
  (an icon-only button), falling back to a glyph only if the upload fails.
- **R3 (C3).** Make the module-page banner resolve to the module's own banner when declared, else the
  framework default — never the dashboard's — and version the banner URLs so a cached image cannot
  pin the wrong banner to a URL.
