# ADR-004: The Fifth Cross-Module Pattern — Global Data Emit

**Status:** Accepted — 18/09/2026
**Deciders:** Dumby Core Engineering — Quixotic Mnemonics
**Supersedes:** The "exhaustive four-pattern" cross-module list as previously stated at blueprint §14.1.
**Governing sections:** blueprint.md 5.0.0 §14.1, §11.17, §18, §24.2, §25, §34

## Context

Blueprint §14.1 declares an exhaustive list of four sanctioned cross-module patterns and
presents it as complete. The v5.0 program requires a capability that list cannot express:
modules publishing durable, schema'd public datasets that other modules and surfaces can
read and aggregate. Without it, that capability either gets built as an unsanctioned
cross-module import (exactly what the pattern list exists to prevent) or the "exhaustive"
claim quietly becomes self-contradictory — the risk the register flags explicitly: the
exhaustive list becomes self-contradictory if the fifth pattern is not amended in the same
edit that documents it.

The competing options were:

1. Keep the list at four and let dataset publication happen outside the sanctioned
   patterns.
2. Document Global Data Emit as a case-by-case exception beneath the four-pattern list.
3. Amend the list explicitly: the pattern count is five.

## Decision

The cross-module pattern list is five, not four. The fifth sanctioned pattern is **Global
Data Emit**: durable, schema'd public datasets exposed through a read/aggregate API.
Blueprint §14.1's list is amended in the same edit that documents the new pattern — the
exhaustive claim never ships in a state that contradicts the pattern it introduces.

## Consequences

- **Module authors** may emit global datasets under the pattern's contract; the emit is the
  sanctioned route, and direct cross-module imports remain banned at their enforcement
  layers.
- **Datasets** are durable and schema'd: payload schemas, runtime membership checks, and
  upload-time consistency reporting apply to them as they do to the events catalog.
- **concept.md** gains the Global Data Emit glossary entry; the §45 compliance matrix is
  regenerated from the Compatibility Ledger with the five-pattern contract versioned.
- **Maintainers** hold the list discipline as an invariant: every "exhaustive" enumeration
  in the corpus states its count, and any change to the count lands as an amendment in the
  same edit — with a superseding ADR if it adds or removes a pattern.
- **Invariant:** cross-module interaction happens only through the five sanctioned
  patterns; there is no sixth by silence.
